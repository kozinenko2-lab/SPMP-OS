# SPMP-OS Stage 31 — gpSP ARMv5: 64-битное целочисленное деление

## Реально сделано

- Добавлен `src/runtime/spmp_aeabi_uldivmod.c`: unsigned 64-bit division без операторов `/` и `%` (исключает зависимость от собственного EABI helper). Функция `spmp_udivmod64` возвращает частное и остаток через указатель. Для нулевого делителя поведение явно определено для внутренних тестов (частное 0, остаток n); вызывающий код должен предотвращать деление на нуль.
- `src/runtime/spmp_aeabi_uldivmod.S`: экспорт ARMv5 EABI `__aeabi_uldivmod`, вход n=r0:r1, d=r2:r3, выход quotient=r0:r1, remainder=r2:r3. Адаптер не применяет ARMv6+ инструкции.
- `tools/build_gpsp_armv5.py`: компилирует C и ARM assembly, связывает их с настоящим gpSP (15/15 исходников), выводит перечень недостающих символов.
- `tests/stage31_uldiv_harness.c`: 200100 сравнений с нативными 64-битными делением и остатком; ASan/UBSan. `tests/test_stage31_uldiv.py`: проверка ARMv5 ELF, присутствия EABI символа, 16 оставшихся импортов и сохранения намеренно не связанных HAL/runtime.
- `make stage31-check`: тесты Stage31 и проверки совместимости Stage29–30.

## Подтверждено в этой среде

- 200100 сравнений: успешно.
- ARMv5 gpSP: 15/15 исходников, объединённый перемещаемый ELF32/EABI5.
- Число неразрешённых импортов уменьшилось с 17 до 16.
- Новые тесты и Stage29/30: успешно.

## Что НЕ сделано

- **Не существует запускаемого и аппаратно проверенного gpSP для Defender**: это объект ET_REL.
- ARM ABI проверен по экспортам и ассемблеру, не исполнением на ARM926EJ-S (нет qemu-arm или реальной платы в этой среде).
- Остаются soft-float helper-ы, `printf`, `sscanf`, `time`, `localtime` и unwind-функции. Для них нужны корректные реализации с совместимым ABI, а не заглушки.
- SD/FAT, LCD, звуковой DMA, Power и точная RAM-карта Defender не проверены.
- В прошивку Flash ничего не записывалось, RedBoot и заводская FSP не изменены.
