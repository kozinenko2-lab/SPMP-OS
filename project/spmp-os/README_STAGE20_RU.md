# SPMP-OS Stage 20 — расширенная ARMv5 сборка PicoDrive

## Подтвержденные результаты

- Для ARM926EJ-S (`--target=armv5te-none-eabi`, ARM EABI5, soft-float) компилируются 31 из 31 выбранного C-файла оригинального PicoDrive: FAME 68k, CZ80, VDP/рендерер, YM2612/SN76496, картридж, RAM, EEPROM, сериализация состояния и дополнительные компоненты.
- `ld.lld -r` объединяет объектные файлы в `build/picodrive_armv5_expanded/picodrive_expanded_armv5_unresolved.o`.
- `readelf` подтвердил ELF32/ARM/ARM926EJ-S/v5TE/EABI5. Три специальных теста прошли.
- Существующий компьютерный тест настоящего PicoDrive `make stage19-md-test` прошёл на тестовом Motorola 68000 ROM: 19 кадров, 13 965 аудиосэмплов, SRAM и повторный запуск.

## Ограничения (важно)

- Объединённый `.o` — НЕ исполняемый модуль и НЕ образ прошивки.
- После частичного связывания 127 неразрешённых символов. Среди них код дополнительных Sega CD/32X-функций, runtime `__aeabi_*`, zlib, файловые и системные сервисы. Нужны корректное отсечение неиспользуемых секций, адаптация системных импорта/библиотек и связка HAL. Подмена символов пустыми заглушками недопустима.
- Заголовки под freestanding toolchain в `tools/arm_picodrive_shim` содержат только декларации: они не реализуют файловые операции, время, аудио и математику.
- Не было аппаратного запуска на Defender, измерений FPS или полноценной ARMv5 сборки SNES/GBA в этом этапе.
- Полный Stage 19 регрессионный прогон был начат, но завершить его не удалось: восстановление Snes9x из исходников превысило время выполнения. Он **не отмечается как прошедший**.

## Проверка

```bash
python3 tools/build_picodrive_armv5_full.py
python3 -m unittest discover -s tests -p 'test_stage20*' -v
make stage19-md-test
```

## Следующие реальные блокеры

1. Убрать зависимости на 32X/Sega CD для строгого профиля MD, либо выделить их в отдельные необязательные модули.
2. Подключить zlib, файловый API и soft-float runtime, после чего добиться полного `--no-undefined` связывания.
3. Реализовать вход/выход из эмулятора через `spmp_core_api`, обработку ошибок, сохранения, меню и Settings в ARMv5.
4. Только после определения RAM и аппаратного HAL — тест на Defender, замеры по кадровому времени и профилированная оптимизация.
5. Затем отдельно проверить облегчённый SNES и GBA.

Оригинальные RedBoot и прошивка не менялись.
