# SPMP-OS Stage 25: исправление синтетического GBA ROM и подтверждение исполнения ARM7

## Исправление
В Stage24 тестовый ROM выполнял `ORR r1,r0,#3` (`0xE3801003`) вместо `ORR r1,r1,#3` (`0xE3811003`). Это приводило к записи некорректного значения DISPCNT и выключению BG2 в видеорежиме 3. Исправление исходной тестовой программы не является исправлением ошибки gpSP.

После исправления gpSP действительно исполняет инструкции ARM7TDMI, записывает `0x0403` в DISPCNT, цвет `0x001f` в VRAM `0x06000000`. Адаптер SPMP-OS выдаёт первый RGB565 пиксель `0xf800` (красный); до исправления он был `0x0000`.

## Проверка
На Linux с host-библиотеками из проекта: `make -j4 stage24-gpsp build/stage24_gba_harness` и `./build/stage24_gba_harness tests/roms/stage24_gba_test.gba`, затем `python3 -m unittest discover -s tests -p 'test_stage25_gba_cpu.py' -v`.

Работают 16 кадров, аудиовывод, save/load состояния и повторный запуск ROM (host x86_64). Все предыдущие модули проекта сохранены.

## Статус ARMv5
gpSP целиком под ARMv5 в этой стадии НЕ собран. Прежний загрузчик/проверка заголовков GBA, а также объект встроенного открытого BIOS `stage25_open_bios_armv5.o`, имеют формат ARMv5 ELF32. Это всё ещё НЕ сборка самого интерпретатора. Необходимо подготовить freestanding libc/libretro runtime и проверить весь интерпретатор на ARM926EJ-S; ARMv6/ARMv7 JIT использовать без отдельной адаптации нельзя. LCD/звук/Power на Defender аппаратно не проверены. Это НЕ готовая прошивка.

Запуск нового набора: `sh tools/stage25_check.sh`.
