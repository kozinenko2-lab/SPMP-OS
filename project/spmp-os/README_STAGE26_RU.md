# SPMP-OS Stage 26 — bounded ARMv5 runtime heap

## Реально реализовано

- В `src/runtime/spmp_heap.c` и `include/spmp_heap.h` появился ограниченный аллокатор `spmp_heap_*`.
- Он работает в **предоставленной извне** области RAM, не выделяет дополнительную память у ОС и не обращается к RedBoot / Flash.
- Реализованы `alloc`, `calloc`, `realloc`, `free`, объединение соседних свободных областей, проверка состояния кучи, защита от переполнения, контроль выравнивания.
- Поддерживается несколько **отдельных экземпляров** кучи для разных модулей. Аллокатор однопоточный; требует внешней сериализации, если к нему обращаются из IRQ и обычного потока.
- ARMv5TE `ELF32 ARM EABI5` компилируется freestanding через Clang, без необходимости в системных заголовках libc.
- 16000 операций с псевдослучайным распределением и проверкой содержимого памяти, ASan/UBSan на ПК, тест повторного освобождения, отказов и слияния блоков.

## Что пока НЕ означает эта сборка

1. Это новый **runtime-компонент проекта**, а не автоматически подключённая замена `malloc` во всех эмуляторах: каждый адаптер должен явно использовать `spmp_heap_*` или пройти проверенную адаптацию функций выделения памяти.
2. Полный ARMv5-бинарник gpSP здесь не собран. Его код ARM7TDMI продолжает работать в прежней компьютерной сборке Stage 25.
3. Входная RAM-область определяется аппаратным HAL после проверки карты памяти. Адреса Defender не предполагались и не подставлялись.
4. Реального запуска на консоли, проверки IRQ, LCD/аудио/SD и установки FSP нет.

## Сборка

```sh
make stage26-check
clang -std=c11 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer -Iinclude tests/heap_harness.c src/runtime/spmp_heap.c -o build/stage26_heap_asan
./build/stage26_heap_asan
```

Новый heap не включён в списки `HOST_SRC`, поскольку это могла бы быть фиктивная интеграция: существующие эмуляторы продолжают использовать собственные правила выделения памяти. При последующей адаптации gpSP/Snes9x/PicoDrive каждый выделяемый блок будет принадлежать ядру, что позволит контролировать переключение платформ.
