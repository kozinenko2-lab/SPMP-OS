# Stage 28 — потоковый файловый HAL gpSP, ARMv5

Реализован **реальный read-only filestream-адаптер** для существующих вызовов Libretro/gpSP, использующий инъекцию файловых функций HAL. Не использует fopen/POSIX и не возвращает ложный успех: без подключённого HAL `filestream_open` возвращает NULL. Полный код — `src/runtime/spmp_gpsp_filestream.c`, ABI — `include/spmp_filestream.h`.

Поддерживаются открытия только для чтения, проверка режима, get_size, seek, read, close, отказ при невалидных указателях, ограничение четырьмя потоками, запрет unbind с открытыми потоками и повторная привязка после выгрузки ядра. Для больших ROM чтение выполняется через колбэки и не требует загрузки всего картриджа в RAM. Принадлежность указателя проверяется до разыменования.

**Тестирование**: 15/15 исходных модулей gpSP компилируются под ARMv5TE, объединяются с новым адаптером в ARM ELF32/EABI5. Неразрешённые внешние имена сократились с 42 до **36**, исчезли все шесть `filestream_*`. Отдельный host-тест с ASan/UBSan проверяет открытие, конец файла, границы seek/read, переполнение числа потоков, повторное bind/unbind. Тесты Stage27 и Stage28 выполняются командами:

```sh
make stage28-check
```

**Что пока не готово**: реальные SD/FAT колбэки SPMP-OS (не проверены на консоли), 36 внешних функций ARM EABI/libc/RTC. Это не запускаемый файл Defender, не FSP-образ и не аппаратно подтверждённый GBA-эмулятор. `filestream_vfs_init` не использует переданный интерфейс Libretro VFS, а маршрутизирует чтение только в заранее привязанный HAL; это намеренное ограничение и не эмуляция POSIX. Запись SRAM и save state остаётся обязанностью уже существующего менеджера сохранений SPMP-OS.

Предыдущие ядра Mega Drive, Sega CD, 32X, SNES, GBA и экспериментальный PSX4ALL сохранены. RedBoot не тронут.
