# SPMP-OS Stage 22 — полный PicoDrive: Mega Drive + Sega CD + Sega 32X

**Статус: компьютерный прототип с проверкой подсистем и ARMv5-подготовка; не готовая устанавливаемая прошивка.**

## Почему раньше Sega CD и Sega 32X были отключены

В Stage 19–21 они отключались **исключительно для локализации ошибок**: базовый Mega Drive (M68K + Z80 + VDP + звук) собирался отдельно от привязанных к нему дополнительных подсистем. Для итогового ядра SPMP-OS это не было техническим требованием. Теперь профиль Mega Drive объединяет все три семейства.

## Что реально подключено в Stage 22

1. **Mega Drive / Genesis** — рабочий на ПК PicoDrive, тестовый 68000-картридж, RGB565, звук, состояния и повторное переключение ROM.
2. **Sega 32X** — код 32X, программный framebuffer, PWM, два SH-2 интерпретатора (без ARM dynarec). В тестовом 32X-картридже Motorola 68000 включает 32X через регистр A15100; проверены создание памяти/подсистемы, 19 кадров, сохранение/восстановление и повторный запуск. **Исполнение инструкций SH-2 в игровом ROM и скорость реальных игр пока не измерялись.**
3. **Sega CD / Mega-CD** — CD-контроллер, PCM и streaming диска. Синтетический CUE/BIN/ISO образ открывается по пути, без загрузки всего диска в RAM; CD-подсистема запускается со *специальным неигровым тестовым BIOS*, проверены кадры/состояния и повторная загрузка. **Это не подтверждение совместимости с реальными CD-играми:** их запуск требует пользовательского соответствующего BIOS, корректных таймингов и тестов.
4. **CHD** — исходный код `libchdr` добавлен из Library пользователя; полноценная библиотека `libchdr` собрана для ПК и реально привязана к хостовой `picodrive_libretro.so`, подтвержден экспорт `chd_open`. **Никакого валидного CHD диска для тестирования не было**, декодирование CHD на игровых данных не проверено. ARMv5-библиотека libchdr пока не связана с основным объектом.
5. **Аудиодорожки Sega CD** — PCM-часть присутствует в PicoDrive; MP3-декодер дорожек в комплект не входит. В тесте музыка CD-DA/MP3 на реальном игровом диске не проверена.
6. **Форматы** — `.md`, `.gen`, `.smd`, `.32x`, `.cue`, `.iso`, `.chd`, `.m3u`. `.bin` требует определения по содержимому / выбора платформы, поскольку двусмысленен; `.cue` и `.chd` также бывают у PS1.

## ARMv5TE (ARM926EJ-S)

`python3 tools/build_picodrive_all_armv5.py` компилирует **51 из 51** выбранного настоящего C-файла: FAME M68K, CZ80, video, YM2612/PSG, 12 компонентов Sega CD и 8 компонентов 32X/SH-2. Результат — `build/picodrive_armv5_full/picodrive_md_cd_32x_armv5.o`, **ELF32 ET_REL/EABI5**, не исполняемый модуль. После частичного связывания остаются **93 неразрешённых символа** (platform HAL, C runtime/soft-float, zlib и другие). Их перечень в `build/picodrive_armv5_full/report.json`.

Не выполнены: полноценное связывание с ARMv5 libc/compiler-rt; ARMv5 CHD и MP3-декодер; реальный графический, звуковой и SD HAL Defender; схема RAM, запуск через RedBoot; пользовательские BIOS и тесты на самой консоли. Не утверждаем, что все игры или игры 32X нормально идут на ARM926EJ-S: для них возможно нехватка CPU или RAM.

## Тестирование

- `python3 -m unittest discover -s tests -p 'test_stage22*' -v`: **6/6** тестов Stage 22.
- `python3 -m unittest discover -s tests -v`: **69/69** тестов всего проекта в рабочем каталоге. Чистая распаковка успешно пересобрала хостовые библиотеки и отдельно прошла MD/CD/32X стенды; общий `stage22-release-check` прерван лимитом среды на повторной ARM-кросс-компиляции. Не утверждается, что полный цикл из чистой распаковки завершён.
- Тестовый код для картриджей/образов создан специально для проекта, коммерческие ROM и оригинальные BIOS не включены.
- Проверено: MD M68K RAM write, 32X ADEN/power up, Sega CD synthetic CUE/BIN/ISO + nonfunctional BIOS, libchdr linked to host, состояние и смена ROM.

### Воспроизведение с нуля на Linux

Нужны: `make`, GCC/G++, clang с `--target=armv5te-none-eabi`, `ld.lld`, `cmake`, `zlib-dev`, `libzstd-dev`, стандартный C++ toolchain и Python3. Имеющиеся тесты могут требовать зависимости сторонних ядер. Команды:

```bash
make -j6 stage22-release-check
# Или отдельно:
make stage22-arm
make stage22-md-cd-32x
python3 -m unittest discover -s tests -v
```

В `third_party/picodrive/Makefile.local` включение `SPMP_CHD_ENABLED=1` добавляет `-DUSE_LIBCHDR` и статические библиотеки CHD для ПК. Сборочный скрипт для ARM **не притворяется**, что libchdr уже нативно связан.

## Принцип хранения игр в SPMP-OS

У всех трёх семей PicoDrive общий ID `megadrive`: переход между ними оставляет загруженным **одно ядро**, заменяет игровое содержимое и при необходимости CD/32X-память. При смене платформы ядро выгружается по общему API. Пункты Continue / Save / Load / Slot / Settings / Exit, скриншот без наложений и короткое нажатие Power принадлежат системе SPMP-OS. **Аппаратная маска Power пока не подтверждена.**

## Безопасность

`firmware/module_catalog.json` помечает `firmware_flashable=false`, `native_firmware_available=false` и `hardware_verified=false`. Установку этого пакета во Flash, RedBoot или SD как готового образа не выполнять. Оригинальная прошивка и загрузчик не менялись.

## Лицензии

Сторонние исходники сохраняют оригинальные файлы лицензий. Перед публичным выпуском нужно проверить применимость лицензии PicoDrive и libchdr, в том числе к объединённой прошивке и распространению бинарников. CD BIOS и ROM пользователя в пакете отсутствуют.
