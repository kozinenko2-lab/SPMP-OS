# Stage 16 — особенности аппаратной интеграции

## Общий API

`spmp_core_ops`: `start`, `tick`, `stop`, `state_size`, `serialize`, `unserialize`, `set_option`. `spmp_core_host` предоставляет чтение ROM, вывод RGB565, PCM, текущие кнопки, сохранение SRAM. Менеджер `spmp_core_acquire` выбирает и удерживает одно ядро. При смене `.sms` ↔ `.gg` библиотека SMSPlusGX не выгружается; при смене платформы освобождается динамический модуль (проверено через `dlopen` на ПК).

## Настройки

Все настройки живут под отдельным ключом ядра. Изменения конфигурации атомарно записываются через абстрактный callback `store_atomic`; хостовая POSIX-реализация использует `fsync` и `rename`. Для eCos/FAT отдельная надёжная запись **не реализована**. Подключённые параметры громкости и Swap A/B действуют через маршрутизатор до входа в ядро.

## ARMv5

`build/spmp_sms_armv5.o` — результат `clang --target=armv5te-none-eabi -mcpu=arm926ej-s -mfloat-abi=soft` и `ld.lld -r`. Не запускать его через RedBoot как ELF executable и не прошивать в NAND: это ET_REL с внешними символами, а адрес загрузки, вызовы HAL и аппаратная карта памяти не определены.

## Сохранения

Пакет SRAM из callback `store_save` нельзя путать с `Save State`: SRAM хранит прогресс некоторых игр, но не CPU/VDP/PSG/RAM. Общий экран Save/Load появится у SMS как активная функция **только после** переносимой сериализации и CRC-проверки, без записи указателей из `state.c` старого проекта.
