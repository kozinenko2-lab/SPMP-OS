# Спецификация резидентного ядра SPMP-OS (рабочий проект)

## Цикл

`UNLOADED → LOAD_MODULE → START_GAME → RUN → PAUSE_MENU → RESUME / STOP_GAME → LOAD_NEXT_GAME`.

- При **PAUSE_MENU** остаются и ROM, и состояние RAM эмулятора, но прекращаются кадры и звуковые вызовы.
- При выборе той же игры → `RESUME` без вызова `start()`.
- При выборе другого ROM того же ядра → сохранить SRAM/RTC, освободить данные ROM/видеобуферы, загрузить новый ROM. Библиотека остаётся открытой.
- При выборе другого ядра → сохранить состояние прежней игры; удалить её память; вызвать release у прежнего ядра; освободить его исполняемый код; загрузить код нового ядра и игру.
- При неожиданной ошибке чтения нового ROM модуль может остаться в RAM для повторной попытки. На устройстве потребуются резерв для меню, watchdog и диагностический журнал.

## Текущий прототип

`spmp_core_launch`, `spmp_core_pause_to_menu`, `spmp_core_resume`, `spmp_core_stop`, `spmp_core_shutdown`, `spmp_core_cached_id`.

Gambatte действительно использует `dlopen` и `dlclose` в Linux-хост-сборке. Это тест модели жизненного цикла, а **не ARM загрузчик**. FCEUmm, TGEmu, z26, CHIP8 пока компилируются в тот же Linux ELF и занимают память независимо от активного состояния. Не использовать показания RSS хостового процесса как бюджет консоли.

## ARM926EJ-S / SPMP8000: что предстоит

Отдельные статически слинкованные ARMv5-EABI модули в ROMFS. Один выбранный модуль копируется во временный слот RAM, после чего требуется корректно применить релокации (включая вызовы и адреса данных), установить stack и .bss, синхронизировать кэши инструкций и данных и передать указатель HAL. При смене модулей слот освобождается. Режим перепрошивки RedBoot не используется для такого переключения.

Перед реализацией нужно подтвердить карту доступной RAM и адреса резервных областей дисплея/DMA на конкретной ревизии Defender. Также требуется отдельный ARMv5 toolchain с C++ runtime для Gambatte. Стандартный ELF с ARMv7/ARMHF тут не подойдёт.

В FLASH/ROMFS должен храниться **весь набор эмуляторов и загрузчик**, но в оперативной памяти — только текущий модуль и его игра, плюс постоянное ядро SPMP-OS. На текущем этапе это архитектурная цель, не функция существующего `.img`.
