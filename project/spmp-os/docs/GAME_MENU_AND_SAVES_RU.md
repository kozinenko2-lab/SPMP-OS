# Единое игровое меню SPMP-OS Stage 15

Независимый от платформы API: `include/spmp_game_menu.h` и `src/ui/spmp_game_menu.c`.

## Логика

- Один короткий Power → `pause()`; меню без выгрузки ROM и кода ядра.
- В меню: вверх/вниз — выбор; вправо/влево — выбор слота (1–5); A — действие; B или короткий Power — продолжить.
- Пункты: **Continue / Save State / Load State / Select Slot / Exit Game**. Английские надписи Stage15 — промежуточный шрифт 5×7; русские надписи потребуют подключения системного Unicode/TTF или встроенного кириллического bitmap-шрифта.
- Exit Game — выйти в библиотеку, код активного ядра по правилам Stage9/10 может оставаться резидентным.
- В интерфейсе Save/Load отображаются приглушёнными, если у ядра ещё нет сериализатора.
- `spmp_ui_router` перехватывает только **первичный RGB565-кадр игры** перед любым оверлеем. Чистый кадр уменьшается до 120×90 с сохранением пропорций и чёрными полями.

## Слоты и формат `.sps` версии 2

Имя: `saves/<core-id>/<fnv64-full-ROM-path>.s<slot>.sps`. Идентификатор ROM хешируется из исходной полной строки, а не из укороченного имени.

Заголовок фиксированный 48 байт, little-endian:

| Offset | Значение |
|---|---|
| 0 | `SPMPSAV1` (8 байт) |
| 8 | format_version = 2, u32 |
| 12 | slot = 0–4, u32 |
| 16 | thumbnail width=120, u16 |
| 18 | thumbnail height=90, u16 |
| 20 | state_bytes, u32 |
| 24 | core-id FNV-1a 64, u64 |
| 32 | rom-id FNV-1a 64, u64 |
| 40 | FNV-1a 32 thumbnail+state |
| 44 | FNV-1a 32 thumbnail |
| 48 | 120×90 RGB565 LE, затем сырые байты сериализатора ядра |

Сохранение и предпросмотр объединены в **одном** файле, поэтому не могут случайно относиться к разным ревизиям игрового состояния. Загрузка сверяет версию, ядро, ROM, слот, длину, полный checksum и только затем вызывает `unserialize()`.

При смене слота считываются **только 21 648 байт** для предпросмотра (заголовок+миниатюра) и проверяется его собственная контрольная сумма. Полный многомегабайтный savestate читается только при команде Load.

На компьютере `src/host/spmp_ui_posix.c` записывает временный файл, `fsync()` и `rename()` в том же каталоге, затем синхронизирует каталог. Это не гарантирует аналогичной crash-consistency на FAT/eCos; файловый HAL консоли должен реализовать и проверить безопасную фиксацию, при необходимости через двойной журнал.

Буфер сериализации предоставляется вызывающей стороной и может выделяться *только на время операции*. Верхний программный предел 8 МиБ; реально допустимый размер зависит от подтверждённой RAM устройства.

## Готовность ядер

- FCEUmm — настоящий libretro `retro_serialize` / `retro_unserialize`, проверено на синтетическом NES ROM на ПК.
- Gambatte — функции `retro_serialize` динамической библиотеки и настоящий GB/GBC ROM, проверено на ПК.
- CHIP-8 — собственная сериализация памяти, регистров, стека, таймеров и экрана, проверено на ПК/компиляция ARMv5.
- Atari 2600, TGEmu, остальные — одинаковое меню, но Save/Load ещё отключены до реализации сериализаторов конкретных ядер.

## Устройство не испытано

ARMv5-объекты меню/рендера/input HAL собраны в ET_REL. Драйверы реального LCD/аудио/FAT, подтверждённые адреса и обработка аппаратного Power ещё отсутствуют. Не прошивать Stage15 в NAND.
