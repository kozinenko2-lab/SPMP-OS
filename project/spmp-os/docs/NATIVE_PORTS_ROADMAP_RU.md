# SPMP-OS: встроенные эмуляторы, игровые движки и технические решения

## Что подтверждено по исходникам

- `libspmp8k-master.zip`: `libgame/start.s` получает указатель на таблицу функций оригинальной системы из **r0**, сохраняет его в `_gFunTable`, очищает BSS, вызывает `_libgame_init` и затем `main`. Это **загрузочный ABI старых NGame-портов**, не рекомендуемый ABI собственной ОС.
- `libgame/libgame.c` сканирует / связывает функции eCos, NativeGE, emuIf, файловые функции. Исходники позволяют составить карту нужных драйверов, но нельзя напрямую переносить абсолютные адреса и поиск прошивки как базу новой ОС.
- `libgame/libgame.mk`: сборка под `-mcpu=arm926ej-s -msoft-float`; использует `mkbing` для прежнего формата `.bin`. Для новой ОС `mkbing` не нужен.
- В том же `libspmp8k` есть исходный код Doom (`demos/doom110`) и эмулятора Atari 2600 z26 (`demos/z26`), плюс утилита ELF→MMP для исследования формата контейнера. Обратите внимание: старый Doom Makefile собирается с `-DNO_SOUND` — звук не готов автоматически.
- `xpectrum`: `src/Makefile.spmp` содержит платформенный `src/spmp/microlib.c`, Z80, TZX/TAP, bzip и файловые интерфейсы.
- `tgemu`: `game.c` использует `emuIfGraphInit`, `emuIfKeyGetInput`, `emuIfSoundPlay`, временные буферы. Поэтому портируем базовый эмулятор, заменяя адаптер eCos собственным.
- `Frodo4`: отдельный `Src/Makefile.spmp` и SPMP меню. Драйверные части переписываются; эмуляция CPU/VIC/SID потенциально сохраняется.
- `wiituka`: в `source/spmp/main.c` есть работа с framebuffer и виртуальной клавиатурой — полезна для Spectrum/MSX/CPC/C64.
- `xrick`: `src/sysvid.c`, `src/syssnd.c`, `src/syskbd.c` — явные аппаратные адаптеры. У исходных игровых карт, звуков и изображений отдельно неясный правовой статус (`README`).
- `scummvm`: большой исходный архив движка; при просмотре `backends/platform/` **не найден** выделенный SPMP backend. Наличие «spmp8000» в имени ZIP не доказывает сборку под устройство.
- `actsemi`: в `config.mk` `mipsel-sde-elf-gcc -march=mips32r2`; это НЕ SPMP ARM SDK.
- `psx4all-dingoo`: `Makefile.dingoo` использует MIPS toolchain и `STD_PSXREC`, поэтому ARM-порт и производительность остаются исследовательскими задачами.

## Новая модель запуска

```text
RedBoot (не изменяем)
  → SPMP-OS (будущее независимое ядро)
     → меню и системный сервис управления памятью
       → регистр встроенных игровых движков
          → Doom  | Quake | Spectrum | z26 | PC Engine | ...
          → ROM/WAD/PAK/сохранения считываются с SD (или другой FS)
```

**Хранить код в прошивке не значит держать все модули в RAM.** Для малой RAM предпочтительна загрузка одного core по требованию с отдельными адресами/ресурсами; нужен независимый формат загрузки и строго заданные границы памяти. **Stage 3 ещё не реализует динамическую загрузку модулей из ROMFS** — реализованы записи реестра, маршрутизация ROM и оригинальный тестовый код, полностью собранный в host и ARMv5 `.o`.

## Основные API будущей системы

1. RGB565 frame present, без прямой зависимости от `gDisplayDev`.
2. Input events / raw buttons / keyboard overlay, все назначения хранятся централизованно.
3. PCM audio output, sample rate conversion, async buffer / underrun log.
4. Virtual filesystem open/seek/read/write, save-state / battery-backed saves.
5. Timers, memory allocation profile, suspension & pause, clean return to menu.
6. Per-core configuration and controlled content selection.

В `include/spmp_cores.h` есть ранний интерфейс V1 с кадрами и кнопками. Он не претендует на окончательный device ABI и потребует расширения по пунктам выше.

## Очерёдность портирования

1. **Z26 / Atari 2600** — небольшой 2D код, удобный первый реальный встроенный эмулятор.
2. **TGEmu / PC Engine** — чёткая граница платформенного адаптера, звук + input + framebuffer.
3. **Xpectrum / ZX Spectrum** — клавиатура, несколько форматов носителей, звук.
4. **Doom** — добавить поддержку звука, проверить память и файловую систему WAD.
5. **Frodo / C64, Caprice / CPC** — виртуальная клавиатура, disk/tape, сложные тайминги.
6. **ScummVM** — отбор лёгких движков, большой размер и значительные требования памяти.
7. **Quake** — требуется исходный код соответствующей сборки либо отдельный открытый порт движка; необходимы профиль памяти и software renderer.
8. **PS1** — самостоятельное исследование, MIPS dynarec не совместим с ARM.

## Подбор содержимого

`.dsk` соответствует как минимум MSX и Amstrad CPC; `.tap` — ZX Spectrum/C64; `.sna` — ZX Spectrum/CPC; `.bin` может относиться к Atari/PS1/другим платформам. Поэтому реестр **возвращает неоднозначность, а не запускает первый совпавший модуль**. В дальнейшем добавим анализ сигнатур / контента и пользовательский выбор.

## Правообладатели и игровые ресурсы

Не смешивать лицензии движков и игровых данных. Doom/Quake требуют собственные свободно распространяемые или полученные пользователем данные; ScummVM также не означает свободного распространения всех поддерживаемых игр. Для xRick в README явно указан неоднозначный статус игровых ресурсов. Перенос GPL-кода в прошивку потребует соблюдения условий лицензии, в частности предоставления соответствующих исходников при распространении бинарного продукта. Объединять модули следует после проверки лицензий каждого источника.

## Перед прошивкой

Пока не подтверждены карта RAM/ROM и оригинальная процедура восстановления, **не создаём загрузочный образ «для прошивки» и не записываем его в NAND**. ARMv5 компиляция `.o` проверяет архитектуру, но не загрузку на устройстве.

## Техническая проба ARM-кода TGEmu (Stage 3)

Проблема обнаружена на реальном исходнике `tgemu/src/cpu/h6280.c`: код использует глобальные фиксированные регистровые переменные GCC (`asm("r7")` для union `PAIR`). При прямой сборке Clang для ARMv5 получены ошибки `bad type for named register variable`. Не нужно переписывать CPU в MIPS или называть этот код неработоспособным: это несовместимость инструментария.

Создан патч `patches/tgemu/0001-clang-armv5-portable-registers.patch`: с флагом `SPMP_PORTABLE_C` использует обычные статические переменные вместо фиксированных регистров, сохраняя существующую логику Save/Restore. Воспроизводимый CPU-only сборщик:

```bash
make arm-tgemu-cpu TGEMU_SOURCE_ZIP=../tgemu-spmp8000-master.zip
file build/h6280_tgemu_armv5.o
```

Успешный результат: `ELF 32-bit LSB relocatable, ARM, EABI5`; экспортированы `h6280_reset`, `h6280_execute`, `h6280_set_irq_line`. Объект пока требует внешние `bank_set`, `io_page_r`, `io_page_w`, `ram`, `read_ptr`, `write_ptr`, `vdc_w`, `memset` и т. п. Для CPU-only smoke-test использованы минимальные объявления стандартных функций вместо полного sysroot: **это проверка компиляции, а не полноценная линковка или запуск PC Engine**. Также следует измерить производительность обычных статических переменных по сравнению со старой GCC-регистровой оптимизацией.

Архив проекта содержит патч и сборщик, но не перепаковывает чужие исходники или собранный объект CPU из GPL-проекта. Для воспроизведения нужен присланный оригинальный ZIP.
