# SPMP-OS Stage 18 — экономия RAM и интеграция игрового runtime

**Дата:** 11 ноября 2026 года.  **Статус:** проверенный компьютерный прототип; не прошивка.

## Реальные изменения

1. `spmp_core_host.file_size` — необязательный предзапрос точного размера картриджа через файловый HAL. Если реализован, адаптер Libretro выделяет ровно указанный объём. Фактический результат чтения сверяется с размером, который сообщил HAL. Отклоняются 0 байт, файлы больше 16 МиБ и неполные чтения. Для старых компьютерных клиентов остаётся ограниченный fallback 16 МиБ. На реальном Defender callback следует реализовать обязательно.
2. Кадровый RGB565-буфер выделяется при получении первого кадра, размером `width * height * 2`, а не всегда 512×512×2. Ветка `RETRO_PIXEL_FORMAT_RGB565` использует построчное `memcpy`, для других форматов сохранено преобразование пикселей.
3. Кнопки берутся один раз при `retro_input_poll`, затем `retro_input_state` читает сохранённую маску. Это уменьшает системные запросы к аппаратному вводу.
4. Настройка Frameskip для Libretro: 0 — выключено; 1 — AUTO (ещё отложено); 2 — вывод каждого второго кадра; 3 — вывод каждого третьего. CPU и звуковая подсистема продолжают работать каждый эмулируемый кадр. Это сокращает стоимость **конвертации и отправки кадров**; FPS на Defender не измерен.
5. Файл SMD Mega Drive теперь можно определить по частичному заголовку (16,5 КиБ), не загружая весь ROM для классификации. Конвертер в нормальный формат остаётся компилируемым под ARMv5.
6. Версия `SPMP_CORE_API_VERSION` поднята **4 → 5**. Загрузчик ARM ELF32 отклоняет объекты с устаревшей версией, прежде чем изменять RAM. Учёт этого важен из-за добавления `file_size` к структуре обратных вызовов.
7. CLI компьютерной версии сообщает размер файлов через `stat`. Добавлен свободный синтетический SNES LoROM на 32 КиБ и проверка загрузки через реальный `Snes9x`.

## Экономия памяти адаптера на тестовом 32-КиБ SNES LoROM

| Буфер | До | После |
|---|---:|---:|
| ROM | 16 777 216 байт | 32 768 байт |
| Кадр RGB565 | 524 288 байт | 114 688 байт при 256×224 |
| Итого только эти два буфера | 17 301 504 байта | 147 456 байт |

Показана экономия размера **двух буферов адаптера**, а не общего потребления эмулятора, ОС или гарантированного размера свободной RAM. Временные потребности во время декодирования/инициализации тоже не измерены. Для игры с ROM 4 МиБ выделится около 4 МиБ, не 32 КиБ.

## Подтверждённые проверки

- `make -j6 stage18-full-check` — все 50 Python-регрессионных тестов, дополнительные тестовые стенды.
- Реальный Snes9x: синтетический LoROM, 16 кадров в тестовом стенде, PCM, полный save-state / restore, два запуска, ошибки ROM.
- Пропуск видеокадров не прекращает подачу аудио.
- Проверка управления памятью ARMv5 и отклонения старого ABI; корпусные тесты непрерывности RAM.
- Файловый Mega Drive SMD-препроцессор компилируется в ARMv5 ET_REL, тестируется на 2 блоках.
- Оригинальный PSX4ALL Stage14-объект остаётся в хранилище **неразрешённым**, запуск запрещён.

## Ограничения

- Исходников PicoDrive в приложенных архивах нет. В этой версии работающий эмулятор Mega Drive **не добавлен**; есть адаптер и подготовка ROM.
- Современный Snes9x собран и выполнен на ПК, **не** полностью связан для ARMv5/SPMP8000, так как нет подтверждённого ARMv5 C++ runtime и аппаратного HAL.
- `retro_input_poll` привязан к Libretro-протоколу. Кнопка Power на реальном Defender по-прежнему не идентифицирована аппаратным измерением.
- RedBoot, NAND и заводская прошивка не изменены. **Архив нельзя прошивать в консоль.**

## Следующие шаги

Получить PicoDrive исходниками; завершить ARMv5 C++ runtime для более лёгкой версии SNES, затем связать оба ядра с интерфейсом SPMP-OS и hardware HAL. Проверить доступную RAM, LCD, аудио и код Power на реальной плате. PSX4ALL оставить экспериментальным до готовности HAL/JIT-кэша.
