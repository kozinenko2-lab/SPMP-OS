# SPMP-OS Stage 46 — SD_P430: CMD18, зависающие опросы, защищённое чтение 512 байт

Дата исследования: 13 ноября 2026 г. **Исследовательский код, не устанавливаемая прошивка.**

## 1. Источники и подтверждения

- `8000_MMI.RAP`, исходный размер **3 284 556 байт**.
- SHA-256: `5529b173b3fb612b2e7f516af807f1342d24ea6f7101be034e1e0d08fed25c4e`.
- ARMv5 первый сегмент начинается с runtime-адреса `0x00280000`, смещение `0x4C` внутри RAP.
- `tools/audit_cmd17_path.py` строго проверяет хэш, 29 конкретных ARM-слов и непосредственные цели переходов из оригинального файла. Результат: `evidence/stage46_sd_path.json`.

Новые подтверждённые участки OEM-драйвера:

| ARM PC | Действие / инструкция | Значение |
|---|---|---|
| `0x002BB004`, `0x002BB008` | `MOV r0,#5504; ADD r0,#18` | формируется `0x1592`, младшие 6 бит равны **18** (CMD18) |
| `0x002BB014` | `BL 0x002B9B78` | вызов штатной отправки команды |
| `0x002BB760`, `0x002BB764` | `MOV r0,#5504; ADD r0,#18` | повторное формирование `0x1592` (CMD18) |
| `0x002BB774` | `BL 0x002B9B78` | второй прямой вызов отправки команды |
| `0x002BB250–0x002BB258` | `LDR; TST #8; BEQ` назад | собственный предел опроса **не найден** в этой ветви |
| `0x002BB274–0x002BB27C` | `LDR; TST #1; BNE` назад | собственный предел опроса **не найден** в этой ветви |
| `0x002BB910–0x002BB918` | `LDR; TST #8; BEQ` назад | собственный предел опроса **не найден** в этой ветви |
| `0x002BB950–0x002BB964` | `ADD; CMP; BHI; ...; BNE` | похожее ожидание, но **ограничено** счётчиком |

В OEM найдено ожидание из Stage45 с пределом 50 001 опрос. Оно не покрывает все другие ветви. Поэтому нельзя считать штатный SD-драйвер защищённым от зависания на всех операциях.

**Не доказано:** какая именно функция реализует полный CMD17, какие значения возвращает SD DMA, где настроены clock/pinmux/IRQ/card detect и физический CRC. Строка `CMD17` в RAP существует, но это не основание заявлять о восстановлении рабочего CMD17-драйвера.

## 2. Новый исходный модуль

Файлы:

- `include/spmp_stage46_sector_guard.h` и `src/spmp_stage46_sector_guard.c`: обёртка **только для чтения**; инициирование операции, ограниченный опрос статуса через Stage45, получение 512 байт во временный RAM-буфер, проверка сигналов backend (`CRC_VALID`, `TRANSFER_DONE`, `CARD_PRESENT`). Только затем происходит копирование в буфер вызывающей стороны. Не больше трёх попыток; после ошибки необходим явный успешный `recover`. Если recovery не сработал — операции прекращаются.
- `include/spmp_stage46_trace.h` и `src/spmp_stage46_trace.c`: общее событие транзакции в RAM-журнал Stage43. При `detailed=1` пишет дополнительное событие с последним словом контроллера и числом попыток. Файловые операции и UART из этого callback запрещены.
- `tools/audit_cmd17_path.py`: воспроизводимая проверка ARM-инструкций в оригинальном RAP.

Обёртка **не реализует SD/MMC backend**: она не содержит указателей на MMIO-регистры, не инициирует DMA, не очищает аппаратный CRC и не выполняет файловую запись. Соответствующие callbacks должны появиться только после проверки на конкретном устройстве. Флаг `CRC_VALID` не вычисляется из RAM-буфера: его должен выдавать верифицированный низкоуровневый backend, знающий статус аппаратного CRC.

**Безопасность fallback:** при отказе SD операция возвращает явную ошибку, а переданный буфер сектора остаётся неизменным. Система выше по стеку должна отказаться от запуска SPMP-OS, при необходимости выполнить независимую проверенную очистку SD-контроллера и продолжить штатную ROMFS-загрузку. Наличие готовой обёртки НЕ доказывает, что fallback RedBoot уже работает на реальном железе.

## 3. Как собрать и проверить

Для standalone-пакета рядом с каталогами Stage43–45:

```sh
cd SPMP-OS_Stage46_CMD17_Guard
make test sanitize arm integrate
make static RAP=/путь/к/8000_MMI.RAP
```

В полном ZIP исходники лежат внутри `SPMP-OS_Stage34/research/redboot_sd_stage46`. Соседние версии называются `redboot_sd_stage43`/`redboot_sd_stage44`/`redboot_sd_stage45`; `Makefile` определяет их автоматически.

Проверено локально:

- C11: 10 000 детерминированных транзакций с перестановкой состояния плюс тесты целостности и отказов (`tests/test_stage46.c`).
- Интеграция с Stage43 RAM-журналом (`tests/test_stage46_trace.c`).
- Статический аудит RAP: 29 машинных слов, 6 unittest и негативный тест изменения ARM-инструкции.
- AddressSanitizer + UndefinedBehaviorSanitizer: C-тесты пройдены.
- LLVM clang ARMv5TE EABI5 soft-float: собран `build/spmp_stage46_stage45_integrated_ARMv5.o`, нет неразрешённых внешних символов (это **relocatable** `.o`, не ELF-приложение).

## 4. Для настоящей записи boot-логов в SD

1. Определить точный ранний SD/MMC интерфейс платы Defender: clocks, GPIO/pinmux, card detect, DMA coherency, IRQ, ошибки CRC и собственные таймауты каждой ветви.
2. Запустить read-only пробу из доверенного RAM-окружения; подтвердить 512 байт LBA0 против дампа SD и повторяемость при извлечении карты. Никаких операций записи, пока не проверен fallback.
3. Проверить установленную ревизию RedBoot и ROMFS-путь штатной системы; резервный запуск должен работать при отключенной SD.
4. Для до-FAT событий использовать RAM/UART; после успешного монтирования — Stage43/44 log exporter. Stage44 установил, что штатный eCos FAT `fsync` здесь ничего не делает, поэтому журнал нельзя считать физически сброшенным после вызова fsync.
5. Определить защищённый межстадийный RAM-диапазон (RAM handoff), а не выбирать адрес наугад.

**Заводские RedBoot, 8000_MMI.RAP, NAND, recovery и SD-файлы не изменялись.**
