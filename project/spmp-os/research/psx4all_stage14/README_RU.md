# SPMP-OS / PSX4ALL — Stage 14: большой прогон и заморозка исследовательской ветки

Дата: 2026-11-11. **Статус: ARMv5-совместимые исходные модули и верифицированный хостовый тестовый стенд. Не готовый консольный порт и не прошивка.**

## Изменения относительно Stage 13

1. `psxTypes.h`: при `SPMP_PSX4ALL` типы гостевого MIPS имеют гарантированную ширину: `u32/s32` строго 32 бита на LP64 и ARM. `s8` сохранён как `char` для совместимости со старым C-строковым API; при сборке ARM включено `-fsigned-char`.
2. `r3000a_new.h`: ширина GPR/CP0/CC0 привязана к PS1, а не к машинному `unsigned long`; прямые зависимости старого исходного кода от ширины указателей выведены в контрольные тесты.
3. `mem.h`, `mem.cpp`: таблицы PS1 memory LUT содержат `uintptr_t`, а размер выделяемых и копируемых таблиц зависит от `sizeof(uintptr_t)`. На ARMv5 это всё ещё 4 байта, на хостовом x86_64 теперь 8 байт без усечения адресов. Убрано усечение адресов в макросах доступа к памяти. `Shutdown()` можно безопасно вызвать дважды; освобождённые указатели обнуляются. Повторный `Init` при активном состоянии отклоняется. При новом запуске сбрасывается состояние cache-isolation записи. `Reset` до инициализации безопасно возвращается.
4. `bios.cpp`: внутренний указатель таблицы переходов BIOS использует 32-битное гостевое представление.
5. `spmp_psx_bios.h`: явный `extern "C"` для линковки C-реализации и C++-ядра без несовпадения имён.
6. Новый изолированный CPU-тест на **оригинальном интерпретаторе PSX4ALL**: LUI/ORI/LW/SW/ADDIU, ветвление BEQ/BNE и branch delay; GTE-заглушки аварийно прерывают тест при случайном обращении к ним — успешные тесты GTE не имитируются.
7. Новая воспроизводимая ARMv5 сборка 33 оригинальных модулей через Clang `armv5te-none-eabi`, включая интерпретатор R3000A, память, GTE, GPU, SPU, CD-ROM, BIOS, HLE, DMA и ARM JIT. Выполнена частичная объектная линковка с переносимыми вспомогательными модулями.

## Сборка и воспроизведение

На Linux с `clang`, `clang++`, `gcc/g++`, `make`, `ld.lld`, `readelf` и `zlib` для тестов:

```bash
make -j4 stage14-release-check
```

Отдельно большой CPU-прогон:

```bash
make stage14-stress
```

ARM-код внутри `build/armv5/psx4all_armv5_core_bridge.o` **не исполняемый ELF**: это один перемещаемый ELF32/ARM EABI5 с неопределёнными ссылками на platform/HAL, libc, libgcc builtins, SPU/CD plugins, C++ runtime и аппаратную графику. Их полный перечень сохраняется в `build/armv5/unresolved_symbols_bridge.txt`.

Заголовки `tools/armv5_headers` — исключительно **compile-time shims** с объявлениями для неподключённого libc/SDK. Это не действующий sysroot и не реализации системных API. Прежде чем запускать на устройстве, придётся собрать корректную ARMv5 runtime-библиотеку и подсоединить драйверы SPMP-OS. Из этого архива нельзя делать прошивку простым переименованием файла.

## Вывод и решение по дорожной карте

Исследовательский этап оптимизации PSX4ALL **закрыт на данный момент**. Достигнута ARMv5-компиляция основных компонентов, устранены критические проблемы со временем жизни PS1/JIT-памяти, проверен настоящий интерпретатор и сохранены регрессии. Перенос в устройство остаётся отдельной интеграционной задачей, зависимой от карты RAM, привилегированной корректной очистки кэша, аудио/видео-драйверов, загрузки CD/BIOS и SPMP-OS HAL. FPS и коммерческая совместимость пока не измерены.

На первой консольной сборке рекомендуем **запуск только через интерпретатор без JIT**. JIT включать после проверки исполняемой RAM, cache/CP15 и теста на устройстве. Не объявлять полную совместимость PS1, пока игры и сохранения не проверены.

Все коммерческие игры и PSone BIOS исключены из ZIP. Оригинальный RedBoot и FSP-образ Defender не модифицированы.
