# SPMP-OS Stage 44 — SD_P430, OEM FAT и сохранение загрузочных логов

**Режим: исследование + программный прототип; устройство не тестировалось.** Никакого патча заводского RedBoot или `8000_MMI.RAP`, ни записи в NAND, ни обращений к MMIO не выполнено. Не использовать `.o` для прошивки.

## 1. Подтверждённый FAT ABI в оригинальном RAP

Проверен SHA-256 `5529b173b3fb612b2e7f516af807f1342d24ea6f7101be034e1e0d08fed25c4e` исходного `8000_MMI.RAP` (3 284 556 байт). Таблица **0x00513CDC** (смещение файла **0x00293D28**) из десяти 32-битных указателей действительно соответствует порядку `cyg_fileops` eCos:

| Индекс | Поле | Адрес функции |
| --- | --- | --- |
| 0 | read | `0x00283F3C` |
| 1 | write | `0x00283FC4` |
| 2 | lseek | `0x00284054` |
| 3 | ioctl | `0x002840E0` |
| 4 | select | `0x00282474` |
| 5 | fsync | `0x00284100` |
| 6 | close | `0x00284108` |
| 7 | fstat | `0x00284188` |
| 8 | getinfo | `0x00284288` |
| 9 | setinfo | `0x002842A8` |

Обратное дизассемблирование `0x00283FC4`: обработчик загружает файл/`uio` и зовёт `0x002A9834`; read вызывает `0x002A92F8`. Успешный вызов записывает результат в `uio` и возвращает нулевой статус; точные поля CYG_FILE / CYG_UIO требуют независимой проверки заголовков конкретной OEM сборки и теста в RAM.

**Критически важно:** `0x00284100` содержит ровно две инструкции `mov r0,#0; bx lr`: файловый `fsync` этой OEM версии — пустая заглушка. Поэтому нельзя считать flush подтверждением записи на физический носитель. Даже успешное закрытие (`close`) не даёт защиты от внезапного исчезновения питания.

## 2. SD_P430: реальный таймаут, пока ещё не драйвер

В процедуре `0x002B9A38`, смещения `0x002B9A5C`/`0x002B9A60`, выполняются `mov r1,#49920; add r1,r1,#80`. Затем цикл с `add r2,#1; cmp r2,r1; bhi ...` проверяет статус (чтение из регистра через косвенный указатель). **Это предел 50 000 итераций**, а не миллисекунды. При интерпретации реального тайм-аута нужна частота CPU/SD и возможная стоимость чтения регистра. Драйвер содержит диагностические строки `CMD12`, `CMD17`, `CMD18`, `CMD24`, `CMD25`, включая ошибки stop/многоблочного DMA, но одних строк недостаточно для восстановления правильной последовательности команд. Адреса `0x92B0B010`–`0x92B0B01C` пока только кандидаты регистров.

В `tools/recover_stage44.py` — строгая проверка исходного SHA, опкодов циклов, таблицы FAT и адресов вызовов. Отчёт: `evidence/stage44_oem_fat_sd_evidence.json`, CSV. Исходные бинарники этот инструмент **не изменяет**.

## 3. Более надёжная запись логов

`spmp_stage44_flush.c` работает с этапом Stage43 (256 событий). Запись открывается через доверенный callback **только после mount**, не более **32 записей** за одну итерацию, затем проверяется результат **close**. В отличие от Stage43 никакой фиктивный `fsync` не позволяет подтверждать прогресс. Ошибки открытия, записи и закрытия не помечают события как доставленные; при повторной попытке возможны дубликаты, которые разбираются по `session + seq`. Нельзя вызывать из обработчиков прерываний и callback FAT, так как возможна рекурсия. Безопасное завершение загрузки заведомо важнее сохранения журнала.

`close_checked` — абстракция: её ещё нужно привязать к конкретным OEM `CYG_FILE` и FAT mount с восстановленной сигнатурой и проверить на устройстве. Код не утверждает, что реальные логи RedBoot или MMI уже записываются.

## 4. Обмен RedBoot → 8000_MMI.RAP через RAM

Новый `spmp_stage44_handoff.c` копирует Stage43 RAM-журнал с заголовком `magic/version/size/session/generation/CRC32/commit`. Метка `commit` пишется последней. При приёме проверяется размер, версия, session/generation, CRC32 и структура каждой записи; повреждения приводят к отказу. Перезапись запрещена при перекрытии исходного и выходного буферов. Это **не гарантия сохранения памяти**: параметр `authorized_region=1` допускается выставлять только если исследование карты RAM доказало, что диапазон зарезервирован, не перекрывается ROMFS/стеками/BSS и не сбрасывается `8000_MMI.RAP`. На данный момент этого доказательства нет, поэтому на устройстве handoff не включён. Возможны ошибки кэша — требуется отдельно доказать протокол D-cache clean/invalidate для ARM926EJ-S.

При отсутствующей SD нужны UART-логи и нормальная загрузка заводской системы. Запись журнала в FAT до mount или из `putc` запрещена.

## 5. Выполненные проверки

- Host C11 с `-Wall -Wextra -Werror`: **10 028 утверждений** (включая 10 000 одиночных повреждений RAM-журнала, сценарии отказа файлового API, разбивку 50 событий на 10+32+8).
- Host AddressSanitizer/UndefinedBehaviorSanitizer: **пройдено**.
- Исходный RAP: **8 Python unittest** с проверкой SHA, структуры указателей, opcodes и диагностики SD.
- ARMv5TE EABI5 soft-float: объект `build/spmp_stage44_with_logger_armv5.o` **создан, ноль неразрешённых символов**. Объектный файл нельзя запускать самостоятельно.
- Оригинальный RAP и RedBoot не изменены.

## 6. Реальные следующие задачи

1. Из исследованного `SD_P430` восстановить **чтение сектора**: машинные команды и регистры, порядок питания/pinmux, завершение DMA и проверку CRC на экземпляре контроллера. Отдельный режим диагностики **только чтение**.
2. Изучить `0x002A9834`, `0x002A92F8` и OEM FAT-mount, собрать официальный адаптер `CYG_FILE/CYG_UIO` с точной ABI-сигнатурой; сначала в RAM-тесте.
3. Определить сохраняемую область RAM RedBoot→MMI и проверить её на устройстве (или использовать UART для первой стадии). Привязывать RAM handoff к «свободному адресу» наугад запрещено.
4. На реальном устройстве проверить штатный RedBoot, независимую возможность восстановления, UART и отсутствие влияния лога на запуск OEM. Только потом вводить SD dual boot.

Не записывайте эти объектные модули в NAND и не запускайте SD/MMIO по неподтверждённым адресам.

## 7. Исправление состава предыдущего архива

В полном комплекте Stage 43 отсутствовал файл `research/redboot_sd_stage42/tests/test_bridge_disk.c`, хотя он был в исходном Stage 42. В Stage 44 он восстановлен из оригинального Stage 42 и включён как отдельно указываемый файл патча. После исправления повторно пройдены **322** сценария FAT Stage 42, **14** сценариев dual boot + 112 усечённых пакетов + 30 000 мутаций, а также все три теста Stage 43.
