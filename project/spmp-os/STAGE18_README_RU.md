# SPMP-OS Stage 18 — снижение расхода RAM для SNES и Mega Drive

**Заводской RedBoot и оригинальная FSP-прошивка не изменены. Это исходники и проверенный компьютерный прототип, не IMG.**

См. [`docs/STAGE18_RU.md`](docs/STAGE18_RU.md) для технических изменений.

Основные улучшения: точное выделение памяти под ROM через HAL, отложенная аллокация RGB565-кадра, опрос кнопок один раз на `retro_input_poll`, ручной frameskip, обнаружение SMD по префиксу и защита версии API 5.

**Проверка:** `make -j6 stage18-full-check`; **демо:** `make stage18-demo`.

# SPMP-OS — Stage 17: Mega Drive, Super NES и экспериментальный PSX4ALL

**Предназначение:** исходный проект и хранилище модулей будущей прошивки. Это **не загрузочный IMG**, не изменение NAND и не прошивка для Defender MultiMix Magic. RedBoot и исходный FSP не изменены. Артефакты ПК предназначены для Linux x86-64, а ARMv5-объекты требуют HAL/релокации/линковки.

## Подтверждённые результаты

### Super NES / Snes9x

- Из присланного `snes9x-master.zip` получена реальная библиотека `third_party/snes9x/libretro/snes9x_libretro.so` для компьютерного Linux. Включены SNES CPU/PPU/APU и остальные модули основной ветки.
- Добавлен `src/cores/libretro_multi_adapter.c`. Интерфейс `spmp_core_ops` управляет жизненным циклом, передаёт кнопки, PCM, RGB565, чтение ROM, SRAM, сериализацию/восстановление игровых состояний. Видео 0RGB1555/XRGB8888 конвертируется в RGB565.
- `tests/stage17_snes_harness.c`: настоящий Snes9x выполняет **10 кадров** на двух тестовых LoROM (программа SEI/BRA), отдаёт 256×224, звук и сериализует/восстанавливает состояние. Проверяется остановка и сохранение резидентного кода при смене SNES-ROM.
- Эмулятор **не собирался и не запускался на Defender/ARMv5**. Основная ветка Snes9x может быть слишком тяжёлой; позже нужна оценка компактного Snes9x 2005 или 2002, с учётом их лицензий.

### Sega Mega Drive / Genesis

- Подготовлен рабочий (на Linux) Libretro-адаптер `megadrive` с общим вводом/выводом, настройками, SRAM и save-state API.
- Исходники *самого PicoDrive* не были приложены к этому набору, поэтому он **не включён в архив и эмуляция Mega Drive не запускается**. Требуемый путь — `third_party/picodrive/picodrive_libretro.so` или переменная `SPMP_PICODRIVE_SO` на ПК. Репозиторий: https://github.com/notaz/picodrive, документация https://docs.libretro.com/library/picodrive/.
- Добавлен настоящий портируемый инструмент `spmp_md_rom.c`: распознавание обычных MD-ROM и SMD, преобразование SMD в обычный порядок байтов **на месте** с рабочим буфером 16 КиБ. Скомпилирован в ARMv5 ELF32 `.o` (`firmware/modules/megadrive/`). Два 16-КиБ блока прошли проверку побайтового соответствия и отказа от повреждённых данных.
- При отсутствующем PicoDrive переключение с текущей SNES-игры на MD отменяется без уничтожения состояния активной игры. На физическом устройстве понадобится отдельная транзакционная проверка ресурсов **до выгрузки** старого ARM-модуля.

### PlayStation 1 / PSX4ALL

- В `firmware/modules/psx4all/` размещены **модифицированные исходники Stage 14 в ZIP**, ARMv5 ELF32 ET_REL `psx4all_armv5_core_unresolved.o`, и полный список неопределённых символов.
- Это **не полноценный исполняемый модуль**. Сохранён статус `RESEARCH`/`native_firmware_available=false` и запрещён запуск из меню до разрешения всех зависимостей. Исходный объект содержит 112 уникальных неопределённых символов (проверяется автоматически; количество может меняться после линковки с HAL).
- Для PSX ещё нужны C/C++ runtime и libgcc soft-float, GPU/SPU/CD/BIOS мосты, подлинная карта RAM и проверка JIT/кэшей ARM926EJ-S. BIOS PS1 не включён.

## Единое меню

Сохранена подсистема Stage 15/16: `Continue`, `Save State`, `Load State`, `Select Slot`, `Settings`, `Exit Game`. Меню по короткому Power включается **только после определения настоящей маски кнопки**. Для состояний SNES используется Libretro `serialize`/`unserialize`; подсистема Stage 15 создаёт миниатюры без интерфейса из исходного игрового кадра. Настройки специфичного ядра применяются только если его адаптер реализовал их.

## Формат модулей и прошивки

`firmware/module_catalog.json` содержит SHA-256, размеры, статус готовности и зависимости. Это макет системного хранилища, **не FSP или ROMFS для установки**. Слоты Stage 10 поддерживают ARM ELF32 ET_REL и требуют настоящего HAL. Linux `.so` нельзя копировать на ARM5 без отдельной компиляции. Источники, содержащие лицензии Non-Commercial (Snes9x/PicoDrive), нельзя использовать без проверки условий распространения.

## Воспроизводимая проверка (Linux x86-64)

```sh
make -j6 stage17-check
```

Тестовая программа SNES использует синтетический свободный LoROM без коммерческих данных. Также можно проверить части отдельно:

```sh
make stage17-test stage17-md stage17-arm-md
python3 tools/stage17_firmware_catalog.py
python3 -m unittest discover -s tests -v
```

## Что осталось

1. Получить исходники PicoDrive, собрать реальный CPU 68000 + VDP + YM2612 + PSG под ARMv5, выполнить диагностический ROM и сравнить FPS.
2. Собрать компактное SNES ядро ARMv5 (основная Snes9x C++ не имеет проверенного bare-metal runtime). Измерить RAM, частоту кадров, совместимость SuperFX/SA-1, тайминги APU.
3. Подготовить PSX4ALL Stage 14 к финальной линковке с HAL: разрешить 112 символов (часть приходится на C runtime), добавить безопасный интерпретаторный режим и проверить производительность на реальной консоли.
4. Определить Power, LCD, SD, звук, память и привилегии CPU для запуска независимой SPMP-OS; не записывать во Flash до проверки восстановления.
