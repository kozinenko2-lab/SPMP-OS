# SPMP-OS Stage 33 — ARMv5 EABI soft-float gpSP, ноль внешних символов

Дата: 2026-11-11. Плата: Defender MultiMix Magic / Sunplus SPMP8000 (ориентир ARM926EJ-S / ARMv5TE).
**Тип продукта: ПОЛНЫЕ ИСХОДНИКИ + ARM relocatable object. ЭТО НЕ готовая прошивка, НЕ RAM-загружаемый исполняемый файл.**

## Что сделано

1. В `tools/build_gpsp_armv5.py` добавлена `-fno-exceptions -fno-unwind-tables -fno-asynchronous-unwind-tables` при компиляции выбранных 15 исходных модулей gpSP, включая два модуля C++. В результате устранены 2 зависимости `__aeabi_unwind_cpp_pr0/pr1`, которые в этом режиме не нужны. Исключения C++ сознательно запрещены.
2. В `src/runtime/spmp_aeabi_softfloat.c` реализованы десять реальных integer-only ARM EABI soft-float entry points (без замены заглушками):
   - `__aeabi_fadd`, `__aeabi_fsub`, `__aeabi_fmul`, `__aeabi_fdiv`, `__aeabi_fcmpge`;
   - `__aeabi_dmul`, `__aeabi_d2lz`, `__aeabi_f2uiz`, `__aeabi_ui2d`, `__aeabi_ui2f`.
3. Арифметика float32/double64 выполняется целочисленными операциями, IEEE-754 round-to-nearest-even, включая нормальные и субнормальные значения, нули, бесконечности и NaN. Полное аппаратное/программное состояние fenv (флаги invalid, overflow, inexact и traps) **не эмулируется**. Для NaN -> int32/64 выбирается ноль, для переполнений целочисленного результата используется насыщение. Эти случаи вне диапазона требуют отдельного ABI-сопоставления с библиотекой Arm, если будут использоваться игрой.
4. ARMv5 ABI проверен `readelf -h/-A`: ELF32 ET_REL, machine ARM, EABI5, Tag_CPU_arch=v5TE. `nm -u` для слинкованного `gpsp_interpreter_core.o` не содержит внешних символов. Объект остаётся ET_REL: ему необходимы конечная линковка, корректная карта памяти, точка входа, HAL и согласование с проприетарной ОС.
5. Добавлены `tests/stage33_softfloat_harness.c`, `tests/test_stage33_softfloat.py`, `make stage33-check` и обновлены прежние тесты 27/29/30/31/32, которые ранее специально ожидали неразрешённые символы.

## Проверки в среде разработки

- `make stage33-check`: PASS, 350000 рандомизированных наборов операндов на 6 арифметических/сравнительных операциях, на конверсиях int/float/double, дополнительно граничные векторы (нулевые, INF, NaN, denorm, переполнение и округление); сверка с нативным аппаратным IEEE-754 на хосте, без fast-math.
- ASan + UBSan: тот же host-harness без диагностик.
- `make stage31-check stage32-check`: PASS. 200100 сравнений деления 64 бит, тесты gpSP Stage29/30/31/32.
- Theme v9: 34 независимые темы, два режима отрисовки: PASS (регрессия).
- `python3 tools/build_gpsp_armv5.py`: ARM 15/15, partial link True, undefined imports = 0.

## Чего **нет**

- ARM эмулятор QEMU / испытание на реальном устройстве отсутствуют в данной среде. Хост-тесты не доказывают отсутствие аппаратных дефектов.
- Нет проверенного загрузчика из RAM, адресов регистров LCD/SD/DMA/audio, карты RAM, интеграции с оригинальным FSP scheduler.
- Нет полноценной конечной ELF/FSP сборки, загрузочного файла для карт памяти или прошивки. RedBoot, Flash и NAND не менялись.
- Десять EABI функций закрывают **только текущий** диапазон gpSP. Другие модули (SNES/PicoDrive/PSX4ALL) имеют собственные зависимости, их нельзя считать готовыми по результатам gpSP.
- Runtime softfloat Stage33 реализован здесь, а не скопирован из upstream LLVM compiler-rt. Возможна последующая замена на проверенную версию compiler-rt/libgcc под точно подтверждённую ABI и лицензией.
