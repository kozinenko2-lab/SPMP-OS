# SPMP-OS Stage 7 — NES baseline, Atari 2600, PC Engine, CHIP-8

**ВНИМАНИЕ: это исследовательская компьютерная сборка и перемещаемые ARMv5-модули, НЕ готовый IMG для прошивки Defender MultiMix Magic.**
Загрузчик RedBoot и оригинальный `mmm-firmware-v3_FSP.img` не изменены. На физической консоли код не испытывался.

## Что добавлено по сравнению со Stage 6

- Подключено новое собственное небольшое ядро NES (`src/cores/nes_nrom.c`) через `spmp_core_ops`: загрузка iNES1, базовый NMOS 6502, чтение/запись PPU, RGB565 256×240, joypad, OAM/DMA (приблизительно), CHR-RAM, простая работа с PRG RAM, отдельное сохранение для батарейных картриджей.
- **Работают в синтетических тестах только мапперы 0 (NROM), 2 (UxROM) и 3 (CNROM)**. Это ограниченное ядро для проверки ядра SPMP-OS. **Не выдаётся за современный полноценный FCEUmm** и не заменяет по совместимости штатную прошивку.
- Поддержка спрайтов 8×8 / 8×16 с предварительным отбором не более восьми спрайтов на строку; снижены затраты на проверку спрайтов.
- Исправлено опасное побочное чтение CPU из записи `STA $2007`, которое приводило к сдвигу PPU-адресов и неправильной палитре.
- Добавлены тестовые ROM, целиком собственные, с проверкой CPU→SRAM, PRG-банков UxROM, CHR-банков CNROM, PPU-вывода, сохранений и повторных запусков.
- Обновлён реестр встроенных ядер и тесты прежних стадий. NES в реестре теперь `HOST_TESTED`, но это означает **только прохождение компьютерного тестового стенда**, не подтверждение игрового каталога.

## Результаты сборки

- `build/spmp-os-host` — компьютерная демонстрация (Linux/x86_64, собрана в этой среде).
- `build/nes_armv5_stage7.o` — ARM EABI5, **ELF32 ET_REL** для ARM926EJ-S, **не** ELF с точкой входа и не `.BIN` для прошивки.
- Объекты ARMv5 Atari 2600, PC Engine, CHIP-8 прежних стадий успешно пересобраны.
- `build/nes-preview.png` — реальный кадр, созданный тестовым iNES ROM.
- 34 автоматических Python-теста прошли, отдельно `build/nes_harness` и проверка NES под AddressSanitizer/UndefinedBehaviorSanitizer.
- По `size` модуль NES использует примерно **11,8 КиБ `.text` и 911 КиБ `.bss`**, не считая всего остального ядра ОС, стека и HAL. Загрузка всех эмуляторов одновременно в RAM не предусмотрена.

## Как запустить компьютерные тесты

Требуются Make, компилятор C, Python 3, для ARM — Clang и LLD.

```sh
make host arm-nes test-cores
python3 -m unittest discover -s tests -v
make arm-pcengine arm-atari arm-chip8
./build/spmp-os-host --cores
./build/spmp-os-host --run-core nes --content samples/nes_cpu_ppu_smoke.nes --frames 2 --screenshot build/nes-preview.ppm
```

В тестовый пакет включены `samples/nes_cpu_ppu_smoke.nes`, `samples/nes_uxrom_smoke.nes`, `samples/nes_cnrom_smoke.nes` и генератор `tools/make_nes_test_roms.py`. Они не содержат чужого игрового кода или коммерческих ROM.

## Неподдерживаемые функции и ограничения

**NES:** пока нет APU/звука, точного цикла PPU, прокрутки на уровне точных таймингов, MMC1/MMC3, NES 2.0, FDS, PAL/Dendy, нестандартных команд CPU и проверки на широкой библиотеке игр. Видео имеет приближённую синхронизацию. Ни одна коммерческая NES-игра не объявлена проверенной.

**GB/GBC, GBA, SNES, Mega Drive:** в этом этапе нет собранных замен заводским ядрам. Записи в реестре — исследовательские. Для дальнейшей совместимости целевые проекты: FCEUmm (NES, GPLv2), Gambatte (GB/GBC), gpSP (GBA, обязательно проверить ARMv5 JIT), PicoDrive (Mega Drive) и Snes9x 2005 (лицензионные ограничения). Возможный лёгкий DMG-прототип Peanut-GB (MIT) НЕ заменяет полноценную поддержку GBC.

**Аудио и мультимедиа:** сохраняются на уровне прежнего компьютерного прототипа. Реальные MP3/видео/FM-драйверы для SPMP-OS пока не выполнены.

**Defender HAL:** точные адреса RAM, LCD/аудио и безопасный способ передачи управления из заводской среды всё ещё не подтверждены. Никаких операций записи NAND/RedBoot в проекте нет.

## Следующая стадия

1. Подключить зрелый исходный FCEUmm: восстановить адаптер API, мапперы, PPU/APU, SRAM, NTSC/PAL, затем составить открытую матрицу совместимости и скорость на ARMv5.
2. Подключить Gambatte с реальным запуском GB и GBC: видео RGB565, выбор палитр, аудио, MBC, RTC и батарейные сохранения.
3. Определить реальный бюджет RAM Defender и добавить загрузку одного core по требованию.
4. Параллельно разрабатывать аппаратные HAL и независимый RAM-boot без изменения RedBoot.

### Лицензии

Собственный NES baseline поставляется по MIT (`LICENSE-SPMP`). Исходный TGEmu и z26 содержат свои копии GPLv2-уведомлений. Прочие компоненты сохраняют свои исходные лицензии. Для будущей полноценной FCEUmm/Gambatte-сборки лицензии следует соблюдать отдельно. Коммерческие ROM/BIOS не включены.
