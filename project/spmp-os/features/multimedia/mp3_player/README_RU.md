# SPMP-OS MP3 Player v4 — независимый модуль

**Статус:** код декодера работает в хост-тестах, ARMv5 EABI5 собран и проверен на полную линковку; **НЕ является прошивкой и НЕ испытан на физической Defender**.

## Что сделано

- Полное программное декодирование MP3 (MPEG Layer III 1/2/2.5), а также MPEG Layer I/II через libmad (с открытыми исходниками, а не безымянные старые закрытые `.O`).
- Оптимизированная fixed-point арифметика ARMv5 `FPM_ARM`, `-O3`, `OPT_SPEED`, `OPT_SSO`, soft-float EABI5.
- Потоковое воспроизведение из FAT/SD через абстрактный callback `read`, `seek`, `size`. 8-КБ буфер входных данных, PCM16 по 576/1152 сэмплов/канал.
- Без heap внутри ARM-кодека: ресурсы `MAD_BUFFER_MDLEN`, overlap и PCM выделены в 48-КБ памяти контекста вызывающего приложения.
- ID3v1/v2.2/v2.3/v2.4 текстовые поля; JPEG/PNG APIC как смещение+размер в исходном файле; нераспознанные и сжатые/шифрованные поля пропускаются.
- Xing/Info VBR-таблица, приблизительный seek с 200-мс прогревом, длительность, коррекция LAME/Lavc delay+padding для стандартных MP3, пауза и громкость.
- M3U/M3U8 потоковый плейлист (BOM, `#EXTINF`, строки Unicode, ограничение пути).
- Независимый аудиоадаптер к `spmp_multimedia_driver` Stage10, и управление: `Start` пауза, `Select` выход, влево/вправо ±5 с, вверх/вниз громкость ±16.
- Без вызовов RedBoot, NAND и кода эмуляторов. Все изменения в `features/multimedia/mp3_player/`.

## Сборка на компьютере

```sh
cd features/multimedia/mp3_player
make all
make check
make armv5_freestanding
```

Для подключения к оригинальному Stage10 (после установки патча в его исходное дерево):

```sh
make armv5_app STAGE10=../../..
```

Готовые ARM-архивы находятся также в `artifacts/`:

- `libspmp_mp3_armv5.a` — собственно кодек + ID3 + M3U;
- `libspmp_mp3_freestanding_armv5.a` — мини-libc/soft-div для независимой проверки линковки (не применять одновременно с иными реализациями AEABI без проверки конфликтов);
- `libspmp_mp3_stage10_armv5.a` — аудиоадаптер;
- `libspmp_mp3_app_armv5.a` — обработчик кнопок и сервис проигрывания;
- `spmp_mp3_linkcheck_armv5.elf` — **только диагностический линковочный образ**, НЕ исполняемая прошивка и НЕ модуль штатного загрузчика.

## Контракт подключения к железу

1. Реальный SD/FAT-драйвер даёт callback `read`, `seek` (в абсолютных байтах) и `size`; `read` может вернуть короткий блок, 0 при EOF, отрицательное значение при ошибке.
2. Реальный PCM/DAC/I2S драйвер SPMP8000 реализует три функции Stage10: `audio_open`, `audio_write_s16` и `audio_close`. Переполнение DMA-очереди и громкость аппаратного микшера — ответственность драйвера.
3. Выделить глобальную/статическую `spmp_mp3_app`, вызвать `spmp_mp3_app_open` с callbacks и затем `spmp_mp3_app_tick` из UI-loop, а `spmp_mp3_app_close` при выходе.
4. Считывание и рисование встроенных обложек — через уже отдельный JPEG/PNG viewer: `cover_offset` и `cover_bytes` указывают на байты внутри файла.
5. Запуск сначала только из RAM; NAND/RedBoot не изменять.

## Тесты и известные ограничения

`tests/verify_mp3.py` генерирует 6 аудиопотоков FFmpeg (11,025–48 кГц, mono/stereo, CBR и VBR). Число PCM-сэмплов совпадает с FFmpeg при наличии gapless-тегов; средняя абсолютная разница около 0,9 единицы 16-bit PCM. Проверяются короткие чтения (19 байт), последовательное чтение, seek и UTF-8 ID3. Дополнительные тесты: M3U, Stage10 bridge, повреждённые заголовки, математика 64-bit ARM (30 тыс. случаев), полная ARMv5 линковка без undefined symbols.

**Что ещё требует аппаратного тестирования:** скорость в реальном времени, нагрузка CPU, температура, выход PCM через DAC и DMA, питание/сон, чтение с обеих карт SD, непрерывная работа несколько часов, latency/underruns. Количество RAM и карта аппаратуры не подтверждены на целевой ревизии.

**Текущие ограничения:** gapless реализован для распространённых LAME/Lavc Xing/Info кадров, но не для всех MP3-энкодеров; seek приблизительный, а не sample-accurate; не поддерживаются некоторые нестандартные/зашифрованные/unsynchronized ID3 кадры; обложки только обнаруживаются, но не декодируются в этом модуле; hardware driver не реализован. M3U парсер возвращает пути, переключение треков и shuffle/repeat реализуются UI-уровнем, не ядром кодека.

## Безопасное объединение с игровой веткой

Корень исходников: `SPMP-OS_Stage10` (не zip). Для аддитивной установки из каталога **пакета патча**, а не из `payload`:

```sh
python3 tools/mp3_patch.py --target /path/to/SPMP-OS_Stage10 --check
python3 tools/mp3_patch.py --target /path/to/SPMP-OS_Stage10 --apply
python3 tools/mp3_patch.py --target /path/to/SPMP-OS_Stage10 --verify
python3 tools/mp3_patch.py --target /path/to/SPMP-OS_Stage10 --remove
```

Установщик сверяет SHA-256, не перезаписывает файлы и отказывается удалять файлы, которые кто-либо изменил после установки. Он ничего не меняет в `src/cores`, `src/loader`, загрузчике, RedBoot или сторонних модулях. Игровая ветка может идти вперёд независимо.
