# SPMP-OS File Manager FM-03 — свойства файлов и каталогов

**Цель:** Defender MultiMix Magic / SPMP8000 ARM926EJ-S / ARMv5TE, экран 320×240 RGB565.

FM-03 — *аддитивный модуль поверх FM-01*. FM-02 для файловых операций поддерживается, но изменять его не требуется. Код FM-03 размещается только в `features/filemanager/FM03/`. Он не изменяет исходники эмуляторов, FM-01/FM-02, темы, ядро или RedBoot.

## Реализовано

- Свойства файла: имя, относительный путь от корня SD, тип, 64-битный размер в байтах, дата и время изменения, признаки read-only/hidden.
- Свойства папки: постадийный рекурсивный обход и суммарный размер всех вложенных *обычных файлов*, число вложенных файлов и каталогов, включая скрытые имена. Сам выбранный каталог в счётчик подкаталогов не входит.
- Доступный/занятый/общий объём тома через backend. В UI показывается `использовано / всего`; `available_bytes` доступен для будущего окна SD.
- Окно поверх FM-01 в 320×240, единый RGB565-буфер экрана, цвета темы, русский/английский текст через `fm01_font_draw` (шрифт прошивки, без растра букв в иконках).
- Инкрементальный подсчёт каталога: один вызов `fm03_tick(&props, 8)` обрабатывает не более 8 записей, чтобы оболочка могла перерисовывать экран и опрашивать B/START. Максимальный бюджет вызова: 64 записи; глубина 16; общий предохранитель: 250000 записей.
- `fm03_dispatch()` перед обработчиками FM-02/FM-01: одновременное нажатие START+SELECT открывает свойства выделенного объекта; B закрывает окно, START прерывает подсчёт, оставляя частичные цифры. Также можно добавить пункт `Свойства` в меню FM-02, вызывающий `fm03_open_selected()`.
- POSIX backend *только для ПК*: относительные пути внутри заранее открытого корневого дескриптора SD, открытие каталогов с `O_NOFOLLOW`, запрет выхода через `..`, пропуск символических ссылок при рекурсивном подсчёте. Не поддерживает доступ к произвольным устройствам и переход через смонтированные другие файловые системы.

## API

```c
fm03_backend callbacks;
fm03_posix_backend(&callbacks); /* только для Linux-тестов; на Defender заменить на FAT backend */
fm03_init(&properties, &fm01_browser, &callbacks, &backend_context);

if (!fm03_dispatch(&properties, pressed_keys)) {
    fm02_buttons(&operations, pressed_keys);
    /* затем FM-01 если FM-02 не поглотил событие */
}
if (properties.state == FM03_SCANNING) fm03_tick(&properties, 8);
fm03_render_overlay(&properties, framebuffer, 320, &colors, &font);
```

`fm03_backend` состоит из пяти callback: `info`, `space`, `begin`, `step`, `end`. Консольный FAT backend должен реализовать их с проверкой корня SD, корректным чтением FAT timestamps, обработкой извлечения носителя и освобождением ресурсов при ошибке/отмене.

## Сборка

После установки FM-01 и FM-03 в общий проект:

```sh
cd features/filemanager/FM03
./tools/build.sh
python3 tools/preview.py
```

Результаты: `build/libspmp_fm03_armv5.a`, `build/fm01_fm03_combined_armv5.o`, хостовый тестовый CLI `build/fm03_props`, библиотека рендерера для ПК `build/libfm03_host.so`, PNG в `previews/`.

CLI:

```sh
./build/fm03_props /path/to/sd-root "MUSIC" "Album"
./build/fm03_props /path/to/sd-root "" "test.txt"
./build/fm03_props /path/to/sd-root "" "BIGFOLDER" 2  # отмена после 2 шагов
```

Установка: `python3 install.py /path/to/SPMP-OS`; проверка `--verify`; безопасное удаление `--uninstall` (команды из корня архива). Изменённые файлы патча никогда не удаляются автоматически.

## Ограничения

- На реальном Defender не проверены LCD, SD/FAT, RTC и физические кнопки. Компиляция ARMv5 **не равна** запуску на консоли. POSIX backend не включать в прошивку.
- Глубина рекурсии ограничена 16 уровнями; превышение возвращает ошибку и не выдаёт неполный размер как окончательный. При отмене отображаются **частичные** показатели.
- Копирование, перемещение, переименование и удаление выполняются предыдущим FM-02. FM-03 не записывает на SD. Проверенный FAT write-backend ещё отсутствует.
- Свободное место в тестах на ПК отражает файловую систему временной тестовой папки, а не физическую SD-карту.
- Использование системного шрифта делает локализацию возможной; полноценный переключатель всех языков — отдельная общесистемная функция.
