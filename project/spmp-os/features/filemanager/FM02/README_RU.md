# SPMP-OS File Manager — FM-02 (файловые операции)

**Статус:** реальные POSIX-тесты (ПК) пройдены, freestanding ARMv5 EABI5 **собран**. Это *не* готовый аппаратный модуль записи в FAT на Defender: проверенный FAT/SD write-backend отсутствует; на устройстве операции запрещены до его подключения.

## Зависимость и независимое объединение

Сначала устанавливается **FM-01**, затем FM-02. Патч FM-02 добавляет файлы *только* `features/filemanager/FM02/`, не меняет исходники FM-01, ядро, темы или эмуляторы. FM-02 импортирует публичный `spmp_fm01.h`, функции модели и системный font callback.

Установка из корня архива:

```sh
python3 install.py /path/to/SPMP-OS
python3 install.py /path/to/SPMP-OS --verify
python3 install.py /path/to/SPMP-OS --uninstall
```

Файловая библиотека под ARMv5: `build/libspmp_fm02_armv5.a`; для готового связанного FM01+FM02 объекта — `build/fm01_fm02_combined_armv5.o`. Бинарники host/Linux не запускаются на Defender.

## Возможности

- **Копирование** выбранного файла или каталога, в том числе с вложенными каталогами (ограничение глубины 16) между панелями. Перед публикацией результата используется временный файл или папка в том же родительском каталоге назначения; при отмене / ошибке временные файлы удаляются. В существующее имя без предупреждения *ничего не записывается* (ошибка `EEXIST`). Для копий файлов и папок сохраняются права владельца (без SUID) и временные метки изменения.
- **Перемещение и переименование** через `renameat2(RENAME_NOREPLACE)` в POSIX-backend, без перезаписи. Работают внутри одной файловой системы; перенос между разделами требует отдельного FAT-backend или специально спроектированной операции copy-verify-delete. При `EXDEV` исходники остаются нетронутыми.
- **Удаление** только после подтверждения A. До фактического удаления выполняется проверка дерева, обнаружение символьных ссылок и возможность отмены. После начала удаления оно необратимо; при ошибке возможна частичная обработка, которая обязательно возвращает ошибку (см. журнал/результат).
- **Множественное выделение**: до 64 имён в одной панели/одном каталоге; обработка последовательно. Если операция 3/5 не выполнена, ранее завершённые 1 и 2 не откатываются автоматически.
- **Прогресс**: подсчёт байтов/объектов для копирования и удаления, callback после каждого блока ~8 КБ; стадия preflight/transfer/commit/remove. API предоставляет неблокирующий `fm02_set_cancel_poll` для опроса B во время синхронного чтения SD.
- **Безопасность**: запрет `..`, `/`, `\\`, UTF-8 с ошибками, символических ссылок, выходов за заданный корень, операций над неподдерживаемыми файлами (FIFO/сокеты/устройства), копирования папки внутрь самой себя. Путь ограничен 511 байт, имя 255 байт.
- **UI:** поверх FM-01 в RGB565, 320×240, системный шрифт (зависит от прошивки и локали). START открывает действия; UP/DOWN выбор, A выполнить, B закрыть; SELECT отметить/снять файл, LEFT/RIGHT выбрать панель. Цвет берётся из темы.

## Переименование и клавиатура

Само переименование реализовано и протестировано, включая кириллицу: можно вызвать `fm02_prepare(m,FM02_RENAME,new_name); fm02_commit(m,1)` или `fm02_supply_rename()` после экранного ввода. **Экранная клавиатура ещё не реализована — это FM-04**. Нажатие на пункт переименования пока переводит UI в `FM02_RENAME_INPUT_REQUIRED` и ожидает внешний ввод.

## Сборка, тесты, RAM

```sh
cd features/filemanager/FM02
./tools/build.sh
python3 tools/preview.py /path/to/themes
FM02_TEST_BINARY="$PWD/build/fm02_ops_asan" ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 python3 tests/test_backend.py
```

`fm02_model` ~17.2 КБ (в основном 64 отмеченных имени), поверх `fm01_model`; **общий RGB565 framebuffer** выделяет ОС — второй экранный буфер не нужен. Для большого каталога FM-01 по-прежнему подгружает 9 записей на панель. Для копирования используется буфер 8192 байт в хостовом backend, не в ядре ARMv5; при переносе на FAT использовать небольшой буфер и предсказуемое выделение в HAL.

## Новый общий механизм копирования (Stage16)

В основной системе добавлены [spmp_file_copy](../../../include/spmp_file_copy.h)
и callback `spmp_fm02_copy_action`: 2-КиБ шаги, временный файл, побайтное чтение
обратно, отмена, no-replace publication и явные ошибки очистки. По 50 host,
ASan/UBSan и compiled ARM926 сценариев, включая вызовы через эту модель FM02.
Он пока обслуживает только COPY обычного файла; Linux backend ниже сохранён.
Живой FAT mutation backend и меню операций в FILES BIN ещё не подключены.
[Отчёт](../../../../../research/boot_reconstruction/STAGE16_REPORT_RU.md).

## Backend для реальной консоли

`fm02_backend_action` — абстрактный backend; `fm02_posix.c` — **только Linux/PC**, с openat(), no-follow, fsync(), renameat2() и защищённым rootfd. Его нельзя линковать в прошивку. Для Defender нужен самостоятельный тестированный FAT backend: конечная запись на SD, обработка извлечения, FAT timestamps, free-space, flush, и безопасное обновление каталога. Пока отсутствует — файловые операции на реальной плате НЕ включать.

Общий продукт продолжится: FM-03 — свойства файла и папки; FM-04 — экранная клавиатура; FM-05 — редактор текста. Не включайте FM-02 в RedBoot/NAND/Flash до полного аппаратного тестирования.
