# Этап 16: копирование для FM02 и интерфейсы изменения FAT

Пользователь сейчас не может проверить консоль и попросил продолжать разработку.
Аппаратная проверка FILES/TTF остаётся отложенной, разработка общих компонентов
продолжается на ПК и ARM926 VM. HOLD по-прежнему не является задачей.

Добавлен общий пошаговый механизм **копирования обычного файла** и callback
для существующей модели FM02. Это новый код в `project/spmp-os`, не готовая
запись на физическую SD: живой FAT backend и меню операций в BIN ещё не подключены.
Пакет Stage15 остаётся read-only. Нового BIN для консоли на этом этапе нет.

## Реализовано

- Задача хранит собственные пути и буферы, не использует heap, FPU или RTOS.
  В ARM-сборке занимает **5740 байт**, два буфера по 2048 байт.
- Пошаговый API выполняет не больше одного блока передачи за вызов. Сами
  синхронные IO callbacks могут блокировать; это не асинхронный драйвер SD.
- Разрешены только относительные пути внутри `SPMP-OS/User/`. Запрещены
  System, абсолютные пути, `..`, пустые сегменты, недопустимые FAT-символы,
  ошибочный UTF-8, завершающие пробелы/точки и слишком длинные пути/имена.
  IO backend дополнительно обязан ограничивать корень, том и переходы по ссылкам.
- Файл назначения должен отсутствовать. В его каталоге создаётся временный
  `.spmp-copy-XXXXXXXX.tmp` с **exclusive create**, до 16 попыток при коллизиях.
  Уже существующий временный файл не становится собственностью задачи.
- Короткие чтения/записи обрабатываются; нулевая запись, ранний EOF, ошибки
  чтения/записи/закрытия и изменение размера/mtime исходника завершают задачу ошибкой.
- После закрытия записи временный файл снова открывается и **побайтно
  сравнивается с повторно прочитанным исходником**. Проверяются EOF и метаданные.
- Только после сравнения и успешного закрытия дескрипторов вызывается
  **атомарный publish_noreplace**. Проверка существования, за которой идёт обычный
  перезаписывающий rename, не соответствует контракту этого callback.
- Отмена возможна до публикации. Ошибка/отмена закрывает дескрипторы и пытается
  удалить только созданный этой задачей временный файл. Если очистка не удалась,
  `cleanup_error` и `owned_stage` сохраняются отдельно от основной ошибки;
  повторный запуск этой задачи запрещён, пока такой остаток не обработан.
  `spmp_file_copy_cleanup` повторяет очистку после ошибки, сохраняя основной
  результат; успешная очистка разрешает следующий запуск.
- Исходник и существующий файл назначения не удаляются. Никакого fallback
  на другой носитель, move через copy-delete или молчаливой перезаписи нет.

Исходник должен оставаться стабильным на время задачи. Сравнение и метаданные
не являются snapshot при конкурентном редактировании/подмене файла. Чтение
обратно может обслуживаться cache: **успех не доказывает сохранность после
потери питания**. Поведение при извлечении физической SD ещё не проверено.

## FM02

`spmp_fm02_copy_action` реализует настоящий `fm02_backend_action` для COPY.
Использует пути двух панелей и имя выбранного файла, передаёт прогресс и отмену.
Существующая синхронная модель FM02 получает callback на каждом шаге; для
device UI предстоит подключить пошаговую задачу непосредственно к циклу событий.
Прогресс включает запись и сравнение: `total=2*size`, без деления в ядре.

Обход каталогов с копированием, MOVE/RENAME/DELETE, множественный выбор в
новом device UI и экранная клавиатура этим кодом ещё не включены. Неподдерживаемое
действие возвращает ENOSYS без IO. Старый Linux FM02 backend сохранён отдельно. Новый механизм пока копирует
байты; перенос атрибутов и временных меток ещё не подключён.

## Оригинальная прошивка

Точный RAP SHA256 прежний:
`5529b173b3fb612b2e7f516af807f1342d24ea6f7101be034e1e0d08fed25c4e`.

| Интерфейс | Адрес | Подтверждено выполнением оригинального ARM |
|---|---|---|
| fatfs_unlink | 0x283858 | Перевод одного пути; disk error -8 → 21, -17 → 200 |
| fatfs_mkdir | 0x2838e8 | Перевод пути; disk error -7 → 20, -20 → 302 |
| fatfs_rmdir | 0x2839a4 | Перевод пути; disk error -7 → 20, -1609 → 22 |
| fatfs_rename | 0x283a34 | Два пути, второй через пятый аргумент/стек; -17 → 200, -20 → 302; другие отрицательные значения могут сохраняться |
| FAT fsync | 0x284100 | `mov r0,0; bx lr`, **ни одного обращения к backend** |
| Координатор rename | 0x2ab6e8 | Блокировка, два resolver вызова, проверка одного тома, вызов driver method +0x6c, разблокировка |

Это не таблица соответствия всем Linux errno: значения 200/302 пока не названы.
Их нельзя автоматически подставлять в общий backend, ожидающий -ENOENT/-EEXIST.
Координатор rename сам не предоставляет флаг NOREPLACE. Семантика метода
драйвера +0x6c требует отдельного восстановления; наличие блокировки само по себе
не доказывает запрет перезаписи. Именно поэтому аппаратного mutation binding
в новой библиотеке нет. Это следующий предмет анализа RAP, независимо от
доступности консоли.

[22 original ARM случая](evidence/file_mutations_arm.json),
[выбранные инструкции](evidence/file_mutations_excerpt.asm).
Lock/path translation/disk/volume-driver boundaries в этих случаях подменены.
Оригинальные образы не менялись. Новых Ghidra exports здесь нет: число выбранных
экспортов остаётся 295; данный результат получен из оригинальных ARM инструкций.

## Проверки и воспроизведение

**50 одинаковых сценариев** выполнены для host, host+ASan/UBSan и compiled ARM926.
Файловые callbacks во всех трёх вариантах работают с настоящими временными
файлами Linux. Это не модель результата копирования: работу делает C-движок,
а в ARM варианте — его скомпилированные ARM инструкции. Linux test backend
использует открытые directory fd, O_NOFOLLOW/O_EXCL и renameat2(NOREPLACE).

Проверены пустой файл, граница блока и длины пути, UTF-8, разные имена, короткий IO,
ошибки/некорректный счётчик callback, недостаток места, порча копии, конкурирующее
готовое имя, коллизии временных имён, отмена на разных стадиях, неудача очистки,
повторный запуск, связь FM02 и закрытие всех дескрипторов. Нулевой fd0 допустим.
Максимальный измеренный стек тестового ARM пути — **2784 байта**, бюджет 8192.
Все CPU-записи и callback outputs ограничены собственной RAM/стеком теста.

Для выравниваемого на 8 байт обнуления добавлен штатный helper `__aeabi_memclr8`;
отдельный minilibc sanitizer harness — PASS, 54026 проверок.

```sh
make -C project/spmp-os file-copy-check file-copy-sanitize-check
make -C project/spmp-os file-copy-arm-check COPY_VM_PYTHON=/path/to/venv/bin/python
python3 research/boot_reconstruction/tools/audit_file_mutations.py \
  --rap /private/8000_MMI.RAP --output /tmp/file_mutations_arm.json
```

[Сборка/хэши](evidence/file_copy_build.json), [host](evidence/file_copy_host.json),
[sanitizers](evidence/file_copy_sanitizers.json), [ARM](evidence/file_copy_arm.json).
GitHub CI повторяет тесты без приватной прошивки и сохраняет анализируемый ELF
в `spmp-file-copy-arm-analysis`. **Этот ELF не является приложением для консоли.**
