# Загрузка RedBoot → MMI: проверенные результаты

Исходники: SHA-256 оригиналов в `evidence/boot_audit.json`.
Проверка выполнена чтением ARM-инструкций; запуска на консоли не было.
Базы Ghidra при этом проходе не открывались. Архивные Stage53–55 — отдельные
предшествующие исследования, а не результаты новой декомпиляции.

## Основная цепочка

```text
RedBoot → /Rom/image/8000_mmi.rap → буфер 0x00A00000
→ MMPi checksum → MMPd entry/count → копирование MMPs
→ go -c 0x00280040 → startup MMI → потоки eCos → GUI и системные службы
```

Это подтверждённый путь штатной функции bootkernel и обычной ROMFS-ветки.
Выбор конфигурации на конкретной Defender пока не установлен.

| Функция | PRAW 1/2/4 | PRAW 3/5 |
|---|---|---|
| stock bootkernel | 0x0004A994 | 0x000467F4 |
| чтение в буфер | 0x00038F0C | 0x00036BF4 |
| разбор MMP | 0x000427A8 | 0x0003E734 |
| go | 0x0004B304 | 0x00046220 |

Предыдущий адрес начала bootkernel 0x0004A998 пропускал MOV ip,sp по 0x0004A994.
PRAW — пять вариантов, а не пять последовательных исполняемых стадий.

В PRAW 3/5 также разобрана ветка 0x36AB4: чтение сегментов прямо в целевую
память. В разобранной функции нет вызова общей проверки сумм 0x3E48C.
Вход в эту ветку зависит от конфигурационных флагов, их смысл ещё не восстановлен.
В RedBoot есть отдельная ветка linux_kernel.rap; это не доказательство наличия
или успешного запуска Linux на Defender.

## Формат оригинального MMI RAP

MMPi: 16 байт; длина 3 284 556 байт; две суммы uint32 LE: DCEDAEE9/A8F5C6B5.
Алгоритм из RedBoot 3/5, 0x3E48C: payload после первых 16 байт разбит на четыре
последовательных участка по floor(payload_bytes/16) слов uint32; остаток слов
принадлежит четвёртому участку. Первая сумма = участки 0+2, вторая = 1+3,
обе modulo 2^32. Это не криптографические подписи.

MMPd по 0x10 имеет длину 36, count=4 по +20, entry=0x280040 по +24.
Загрузчик учитывает маску 0xF0000 в поле +16 перед принятием entry и игнорирует
entry=0xFFFFFFFF. Семантика остальных битов не установлена.

| Смещение заголовка MMPs | Назначение | Длина payload |
|---|---|---|
| 0x34 | 0x00280000 | 3059088 |
| 0x2EADDC | 0x006C8FE0 | 223296 |
| 0x321634 | 0 | 0 |
| 0x32164C | 0x9D807180 | 2024 |

MMPs имеет заголовок 24 байта, общую длину по +4, назначение по +8.
Реконструированный ранее ELF исключал последние два блока. Загрузчик проходит
все четыре; последний содержит ARM-код. Нельзя считать этот высокий адрес обычным
свободным RAM: назначение области ещё нужно установить.

## Передача управления и startup

В stock-функции формируются argv: go, -c, строковое entry. В 3/5 обработчик
0x46220 создаёт контекст, вызывает 0x4AB00, затем трамплин 0x45BDC выполняет
BLX r0. Опция -c обозначена строкой "go with caches enabled". Нельзя предполагать
отключённые кэши. Передача включает работу с CP15 и исключениями; это не простой
C-вызов с установленным публичным ABI.

По 0x280040 MMI снимает бит high vectors CP15, устанавливает векторы, стеки
и обнуляет [0x56AD90,0x6C8FE0), включая запись слова по 0x6C8FDC.
Этот интервал не подходит для сохранения данных через штатный startup.
Далее вызываются 0x299C90, 0x2976D0, 0x299A98 и bootstrap 0x297CE8.
0x299A98 обходит таблицу указателей в обратном порядке; назначение отдельных
элементов требует дальнейшего анализа.

0x297CFC вызывает конструктор Demo GUI 0x2807C8, затем 0x297D00 вызывает
0x33C0FC (путь старта планировщика по прежней карте eCos). GUI entry=0x3BE5B0;
0x3BE5CC вызывает координатор 0x447640. Он выполняет read-modify-write
по 0x90005040 с OR 7 и инициирует системный поток. Назначение MMIO не установлено.
Статические зависимости создания потоков не доказывают динамический порядок
их исполнения.

## Границы результата

Восстановлен host-инспектор структуры и сумм, а не полный OEM loader или MMI.
Не поддержанная в инспекторе ветка MMPh наблюдается в коде RedBoot; она не нужна
для предоставленного несжатого RAP. Реализация MMPh ещё не восстановлена.

Остаётся: BootROM/ScanRam и выбор PRAW под плату; условия bootcfg; карта MMU/RAM;
назначение высоких сегментов; ABI eCos/драйверов; экспорт и сверка баз Ghidra;
проверяемые C/ASM-модули startup. Возврат из новой оболочки и аппаратное
восстановление пока не доказаны. Flash-образы не создавались.
