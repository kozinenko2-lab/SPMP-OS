# SPMP_PROBE_VM.bin — экспериментальное RAM-приложение

Статус опубликованного artifact 14076639604: **USER_CONFIRMED_ON_CONSOLE**.
14 ноября 2026 пользователь сообщил о запуске на консоли: один кадр с тремя
цветными полосами и выход из приложения. Это диагностический прототип на базе
SPMP-OS, а не законченная оболочка или Flash/NAND-прошивка.
Он использует штатный NGame/BIN путь MMI и не заменяет RedBoot или RAP.

В ожидаемой версии MMI приложение проверяет совместимость, рисует один кадр
полос/курсора и возвращается. Выход на первом poll — по маске `0x80000`.
Собственных heap, потоков, аудиоресурсов и файловых записей нет.

До очистки BSS startup вызывает preflight, который проверяет:

- API argument `0x5EFB74`, все 85 слотов и CRC32 первых 32 байт девяти функций;
- kind=6, ненулевую базу Game allocation, capacity и границы code/BSS/load span;
- cached shell stack owner, положение SP и выбранный запас 8 КиБ;
- оба virtual framebuffer pointer: extent, alignment и отсутствие пересечений.

При отказе preflight возвращает status, не очищая BSS и не вызывая graphics/input
API. Сохранение регистров уже использует стек вызывающего. Ожидается штатный
MMI BIN context с доступным word-aligned стеком, а не произвольная точка запуска.
Привязка повторно проверяет профиль перед выдачей типизированных указателей.

Профиль получен офлайн только из оригинального RAP с SHA-256
`5529b173b3fb612b2e7f516af807f1342d24ea6f7101be034e1e0d08fed25c4e`.
Runtime table/CRC проверки определяют совместимость выбранных интерфейсов;
они не вычисляют SHA всего загруженного RAP и не удостоверяют неизменность
остальных инструкций. Другая прошивка требует отдельного проверенного профиля.

## Проверки и границы результата

Локальный пакет принят оригинальным RAP в ARM926 VM: штатные file/header/cipher/
footer/API-init/normal-return функции исполняются. Graphics/input, cache/CP15,
audio/thread и внешние backend подменены явно. Публичный CI использует отдельный
synthetic profile и собственные тестовые байты, а не приватную прошивку.

69 Python-тестов, 116 binding/probe ARM-сценариев, 6 сценариев исходного RAP.
Пользователь дополнительно подтвердил видимый кадр и выход на настоящей
консоли. Детали LCD/GPU, cache/IRQ, адреса выделений на плате и завершение потоков
MMI этим наблюдением не измерены; кнопки и длительная работа ещё не проверены. Ошибки штатного cleanup из этапов 5–6 остаются
свойствами оригинала, который не исправлялся.

Заголовок создан заново: `NGame1.0`, 128 байт, собственное имя, extra tail=0.
LCM byte=5 наблюдался у рабочей игры пользователя. Остальные нетрассированные
поля нулевые. Проверка loader не подтверждает полную обработку metadata/icon/LCM
файловым менеджером устройства. Пользовательский запуск подтверждает принятие
именно этого пакета данным launch route. Header/ресурсы/EXIF игры не скопированы.

## Сборка и артефакты

```sh
# clang, ld.lld, llvm-nm и Unicorn из requirements-emulation.txt.
make -C research/boot_reconstruction arm-native-check \
  ARM_VM_PYTHON=/path/to/venv/bin/python
```

CI artifact **native-probe-ngame-vm-tested** содержит:

- `SPMP_PROBE_VM.bin` — собственный NGame, не ELF с изменённым расширением;
- `native.elf`, `native.map`, `native_layout.json` — исходная раскладка;
- `native_package.json` — SHA-256 конкретной сборки и размеры;
- `native_binding_vm.json` — публичные synthetic ARM-прогоны;
- этот README.

Артефакт хранится 14 дней. Source/compiler variation меняет машинные адреса
внутри приложения и SHA пакета; manifest относится только к соседнему BIN.
Synthetic ELF не включён в этот artifact: его CRC references предназначены
только для тестов, на настоящей MMI он должен отказать в preflight.
