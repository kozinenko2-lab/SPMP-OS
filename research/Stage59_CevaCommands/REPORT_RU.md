# Отчёт Stage59

Главный результат: ранее безымянные C0/C1/C2 — не общий JPEG API, а конкретный
ABI MJPEG-кодировщика функции видеозаписи. Это подтверждено одновременно
путями IMG, строками `EncodeInit`/`Encode1Frame`, callsite рабочего потока и
полями control block.

Восстановленные поля 0x60-байтной структуры: входной кадр `+0x04`, рабочая
память/handle `+0x10`, её размер `+0x14`, ширина/высота `+0x18/+0x1c`,
bitrate/config `+0x20`, fps `+0x24`, GOP `+0x28`, rate control `+0x44`, VLC
buffer `+0x4c`, размер результата `+0x50`, flags `+0x54`, результат init
`+0x58`. Глобальная структура находится по `0x0055866c`.

OEM-код небезопасен как готовый шаблон: mailbox NULL зависает навсегда,
EncodeInit повторяется без лимита, а normal close сначала освобождает `+0x10`
и только затем отправляет C2. В SPMP-OS нужны конечные сроки ожидания,
отслеживаемое владение буферами и проверка диапазона до вычисления alias.

Аппаратный тест CEVA пока намеренно не строится: неизвестны точные границы
динамического shared pool, а ошибка может повредить память или повесить OEM
цикл. Вместо этого создан `SPMP_ALIAS_TEST.bin`, который на реальной консоли
без записи проверяет фундаментальный RAM alias на собственном блоке данных.
