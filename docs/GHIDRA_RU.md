# Ghidra: импорт и восстановление MMI/RedBoot

Оригинальные пользовательские базы Ghidra `ghidra/user_GZF/*.gzf`: MMI, RedBoot v1 и v3. Они созданы в Ghidra пользователем и содержат сохранённый автоанализ. Если ваша версия Ghidra поддерживает восстановление `.gzf`, откройте File → Restore Project / Restore Program из GZF (пункт зависит от версии). Если несовместимо, используйте ELF из `ghidra/Stage52_ELF_Imports/SPMP-OS_Stage52_Ghidra_Imports/elf`.

**Проверка импортируемого CPU:** ARM: little-endian, 32-bit, ARMv5TE (ARM926EJ-S); ARM executable mode; не выбирать ARM64. В подготовленных ELF выставлены реальные виртуальные адреса, обычно MMI начинает с `0x00280040`, RedBoot с `0x00030040`. Уточнить анализатором Ghidra код против данных, включая ARM literal pools.

Инструменты и данные: `research/Stage53_to_55/SPMP-OS_Stage53/ghidra_scripts/SPMP_ExportArchitecture.java`, `...Stage54/...`, `...Stage55/ghidra_scripts/SPMP_Stage55_GUI_DeepExport.java`. В комплекте исходный Java-код; совместимость скриптов с установленной версией Ghidra не подтверждена. Открывать через Script Manager, задавая каталог скриптов. Не применять скрипты, меняющие память, без резервной копии GZF.

**Первая таблица адресов:** `0x00280040` startup MMI; `0x002807C8` запускает GUI; `0x003BE5B0` поток GUI; `0x00447640` координатор; `0x00447540` поток инициализации; `0x004473BC` фон; `0x00339AAC` создание потоков; `0x00460250` запуск внутреннего кода (по машинным инструкциям); `0x00298B64` выключенная диагностика.

Адреса RedBoot v1/v3 проверять **в соответствующей базе**, не переносить между OEM семействами. Нельзя приравнивать OEM загрузочный адрес `0x00A00000` к свободному участку RAM или к точке входа MMI.
