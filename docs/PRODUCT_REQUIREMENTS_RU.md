# SPMP-OS: основное ТЗ

Дата: 14 ноября 2026, Europe/Moscow. Основание — семь пунктов пользователя
в текущем обсуждении. Это целевые требования, **не перечень готовых функций**.
Фактическое состояние: [аудит](PRODUCT_AUDIT_2026-11-14_RU.md).
Очередность: [дорожная карта](PRODUCT_ROADMAP_RU.md).

## Назначение и границы

Новая система для Defender Multi Mix Magic / SPMP8000: оболочка, модульные
эмуляторы и приложения, мультимедиа, файловый менеджер и общие настройки.
Первый рабочий вариант развивается как RAM-приложение под заводской MMI/eCos.
Независимая загрузка — отдельный последующий этап исследования RedBoot.

Все семь направлений входят в целевой продукт. Разделение на очереди не
исключает поздние функции из ТЗ. Детали нового оформления пользователь даст
позже; существующие темы не считаются принятым дизайном.

## 1. Эмуляторы и модульная система

| ID | Требование | Проверяемый результат |
|---|---|---|
| EMU-01 | Обновлённые версии ядер штатных систем | Для каждого выбранного ядра зафиксированы upstream/revision, ARMv5-сборка, совместимость ROM, память и измеренная скорость на консоли |
| EMU-02 | Дополнительные системы, включая существующие SPMP homebrew | Реестр различает работающее ядро, доступные исходники и исследовательскую запись; наличие имени в списке не выдаётся за поддержку |
| MOD-01 | Добавление, удаление и обновление эмулятора без изменения SPMP-OS | Установка/удаление отдельного пакета на носителе изменяет каталог после пересканирования; BIN оболочки остаётся побайтно прежним |
| MOD-02 | Совместимость пакетов | Проверяются тип, версия API, архитектура, нужные службы и память; несовместимый пакет получает понятную причину отказа |
| EMU-03 | Общий жизненный цикл игры | Запуск, пауза, продолжение, выход, смена игры/ядра с освобождением ресурсов и возвратом в оболочку |
| EMU-04 | Сохранения и настройки | Battery saves, save states и настройки по возможностям ядра; обновление модуля не удаляет пользовательские данные, несовместимый state отклоняется |

Пользователь отдельно указал существующие порты ULI/других авторов: Atari2600,
PC Engine, Sega Master System/Game Gear, Neo Geo Pocket, MSX, Doom и Quake 1,
а также другие нетребовательные системы. Их нужно включить в каталог
исходных кандидатов и по возможности обновлять с сохранением полезных
SPMP backend. Полнота текущего статического реестра не является границей ТЗ.

Под «новой версией» понимается выбранная актуальная поддерживаемая ветка с
подходящим ARMv5 backend. Самая новая ветка upstream не гарантирует приемлемую
скорость ARM926. Конкретные версии выбираются после сравнения памяти,
совместимости и производительности; обязательства запустить любую систему
с полной скоростью из ТЗ не следует.

Предлагаемая базовая схема: один активный игровой модуль, общие VFS, графика,
звук, ввод и время. Каталог пакетов на SD, стабильный ID приложения, данные
игры и сохранения отдельно от каталога версии. Версии API и размер структур
должны проверяться явно. Формат манифеста/SDK предстоит утвердить на первом
реально загружаемом модуле; существующий API v5 пока не объявляется стабильным.

## 2. Homebrew-порты и native-игры

| ID | Требование | Проверяемый результат |
|---|---|---|
| PORT-01 | Пакеты портов по принципу PortMaster | Отдельный пакет содержит описание, исполняемую часть, параметры запуска, требования к данным и управление; обновляется отдельно от оболочки |
| PORT-02 | Общие службы для портов | Доступны VFS, ввод, видео, PCM, часы, выделение памяти, пауза и возврат по согласованному API |
| NATIVE-01 | Совместимость с существующими native/homebrew BIN | Поддерживаемый OEM NGame имеет отдельный проверенный маршрут запуска и возврата; произвольный `.bin` не считается приложением по расширению |
| PORT-03 | Отдельные игровые ресурсы | Пакет движка не требует встраивания ROM/WAD/PAK в SPMP-OS; версии движка, лицензии и требования к пользовательским данным учитываются раздельно |

PortMaster задаёт удобство установки/запуска. Linux ELF, shell-скрипты и
библиотеки PortMaster не становятся совместимыми с eCos автоматически.
Для OEM NGame нужен специальный механизм передачи управления: повторная
загрузка по `0xA00000` поверх работающей оболочки не является допустимым
вложенным вызовом. Этот путь исследуется отдельно от модулей нового API.

## 3. Мультимедиа и книги

| ID | Требование | Проверяемый результат |
|---|---|---|
| AUDIO-01 | MP3 и другие музыкальные форматы | Реальное декодирование и звук на консоли; перечень форматов, ограничений и backend опубликован |
| AUDIO-02 | Управление воспроизведением | Пауза/продолжение, остановка, перемотка, предыдущая/следующая композиция, очередь/плейлист |
| VIDEO-01 | MP4, AVI, MOV | Для каждого контейнера указаны работающие видеокодеки/аудиокодеки, профили, разрешение и частоты; проверяется изображение вместе со звуком |
| VIDEO-02 | Управление видео | Перемотка с корректной синхронизацией звука/кадров, пауза, остановка, предыдущий/следующий файл, нормальный выход |
| IMAGE-01 | Просмотр изображений | Предыдущий/следующий файл, вращение, масштабирование/перемещение, слайдшоу и миниатюры; декодеры работают в бюджете памяти |
| BOOK-01 | TXT, PDF, FB2, RTF | Книги открываются на консоли; большие файлы не требуют полного размещения документа в RAM |
| BOOK-02 | Разные кодировки | Есть преобразование в общий Unicode-текст и ручной выбор кодировки при неоднозначном определении |
| BOOK-03 | Удобство чтения | Предлагаемые общие функции: размер шрифта, переносы, сохранение позиции и закладки; финальный UI уточняется на этапе читалки |

Первый предлагаемый набор кодировок TXT: UTF-8, UTF-16 LE/BE с BOM,
Windows-1251, KOI8-R, CP866; список можно расширять без изменения интерфейса
читалки. Это инженерное предложение, а не ограничение пользовательского ТЗ.
PDF — самостоятельный renderer/decoder, FB2 — разбор XML и потока текста,
RTF — парсер управляющих последовательностей. FM05 нельзя подменить ими.

Для музыки первыми кандидатами служат имеющиеся MP3/libmad, WAV PCM/IMA,
FLAC и OGG/Tremor. AMR/WMA/AAC и другие форматы требуют отдельных решений.
MP4/AVI/MOV — контейнеры: распознанный заголовок не означает воспроизведение.
Штатные аппаратные/закрытые кодеки рассматриваются через восстановленный ABI;
наличие файла кодека в FSP не доказывает доступность декодера приложению.

## 4. Файловый менеджер

| ID | Требование | Проверяемый результат |
|---|---|---|
| FILE-01 | Две независимые панели | У каждой свой том, путь, курсор и история; большие каталоги подгружаются страницами |
| FILE-02 | Копирование, перемещение, удаление, переименование | Файлы/каталоги, несколько выделенных элементов, конфликты имён, прогресс, отмена и ошибки носителя; источник не удаляется до успешного завершения копии |
| FILE-03 | Запуск из менеджера | Игры, порты, native-игры и мультимедиа проходят через общий dispatcher; неоднозначный формат предлагает выбор, неподдерживаемый не запускается вслепую |
| FILE-04 | Дополнительные существующие функции | Сохранить полезную основу свойств, UTF-8-клавиатуры и текстового редактора FM03–FM05 |
| FILE-05 | Работа между томами | Копирование между SD и пользовательским внутренним томом; межтомовое перемещение реализуется как завершённая копия и лишь затем удаление источника |

Операции пользовательских файлов во внутреннем томе требуют подтверждённых
границ тома и файлового API. Они не означают доступ к сырому NAND, загрузчику,
ROMFS или служебным разделам. POSIX `renameat2/fsync/openat` нельзя просто
перенести в MMI; гарантии записи и восстановления должны проверяться на FAT.

## 5. Темы, звуки и шрифты

| ID | Требование | Проверяемый результат |
|---|---|---|
| STYLE-01 | Полностью переработанные функциональные темы | Общий механизм оформления применяется к оболочке, менеджеру, диалогам, настройкам и приложениям; конкретные макеты/поведение уточняет пользователь позже |
| STYLE-02 | Настраиваемые звуки | Звуки старта, штатного завершения и действий кнопок, выбор/отключение и громкость; без блокировки навигации декодером |
| FONT-01 | Пользовательские шрифты | Загрузка/выбор, размер, Unicode и резервные символы, проверка повреждённого/слишком большого файла |
| STYLE-03 | Общие параметры текста | Цвета текста и другие согласованные параметры применяются системно, а не независимо в каждой копии UI |

Старые v7/v8/v9 и 34 комплекта ресурсов — материал для сравнения и тестов,
не целевой дизайн. Из них можно сохранить проверяемые UTF-8/bitmap/font и
RGB565-примитивы, не сохраняя старые макеты и формат темы как обязательные.
Формат пользовательского шрифта (готовый bitmap либо импорт TTF/OTF) ещё
нужно выбрать по бюджету памяти. Формулировка «пользовательский шрифт» не
должна превратиться в единственный встроенный алфавит.

Звук выключения возможен при управляемом завершении. Его нельзя обещать при
аппаратном обрыве питания; отдельный shutdown hook ещё предстоит восстановить.

## 6. Аппаратура и внешние устройства

| ID | Требование | Проверяемый результат |
|---|---|---|
| HW-01 | Телевизор по RCA | Физический вывод изображения, PAL/NTSC, переключение/возврат и правила масштабирования проверены на конкретной плате |
| HW-02 | Микрофон | Восстановлен и проверен тракт ввода звука; конкретное приложение записи — последующий UI-этап |
| HW-03 | Камера | Определены сенсор/драйвер, захват и формат кадров; preview/снимки планируются после подтверждения API |
| HW-04 | Mini USB и комплектные джойстики | Определены электрический режим/протокол, обнаружение и отключение; для поддерживаемых игр ввод минимум двух игроков передаётся раздельно |

RCA, микрофон, камера и комплектные джойстики указаны пользователем как
возможности консоли. Универсальный USB host/HID/OTG остаётся гипотезой:
наличие разъёма и аксессуаров не устанавливает поддерживаемые классы USB.
Возможности разных вариантов платы выявляются через профиль устройства.
HOLD отложена; готовность остальных разделов от её идентификации не зависит.

## 7. Общие настройки

| ID | Требование | Проверяемый результат |
|---|---|---|
| SYS-01 | Несколько языков | Общий каталог строк, как минимум существующие русский/английский как первый набор; смена языка действует на все новые экраны |
| SYS-02 | Время и дата | Чтение/установка настоящих часов при доступном RTC, сохранение и проверка после повторного запуска; фиктивное время эмулятора не выдаётся за RTC |
| SYS-03 | PAL/NTSC телевизора | Настройка связана с HW-01; отличается от региона эмулируемой консоли |
| SYS-04 | SD и внутренняя память | Оболочка видит оба пользовательских тома одновременно; панели могут открывать разные тома, снятие SD не повреждает другую панель |
| SYS-05 | Шрифты, цвета и остальные общие предпочтения | Версионируемый конфиг, значения по умолчанию, проверка диапазонов и восстановление после повреждения/отсутствия файла |
| SYS-06 | Сброс настроек | Сбрасываются настройки SPMP-OS; игры, сохранения, книги и носители не форматируются и не удаляются |

`sd:/` и `internal:/` предлагаются как логические имена VFS, а не как уже
подтверждённые пути заводской MMI. Два зарегистрированных storage driver не
доказывают одновременную работу двух томов: возможны общие глобальные состояния
OEM. Это обязательный исследовательский вопрос для SYS-04/FILE-05.

## Общие критерии готовности

- На каждом этапе различать исходник, host-тест, ARM-линковку, ARM VM и
  пользовательское подтверждение на консоли, с привязкой к версии пакета.
- Для модулей/кодеков публиковать зависимости, происхождение, лицензии,
  ограничения и фактические замеры; не включать закрытые OEM бинарники
  и пользовательские игровые данные в публичный репозиторий.
- Общие службы контролируют файловые дескрипторы, память, звук, ввод и
  возврат. Адреса MMI остаются в image-specific backend, не в каждом порте.
- Ошибки модуля, кодека, профиля или SD должны давать сообщение и ожидаемый
  способ выхода. Нативные модули делят адресное пространство MMI: полной
  изоляции произвольного ARM-кода текущая архитектура не предоставляет.
- Сохранить рабочий заводской запуск. Настоящий RAM-бюджет, cache/IRQ/cleanup
  и многократные переключения проверяются до заявления о готовой системе.
