# Каталоги системы и пользователя на SD

Формат `SPMP_OS_SD_LAYOUT_V1`. Основание — просьба пользователя разделить
системные файлы/библиотеки и пользовательские ROM/мультимедиа. Это логическое
разделение **на SD**, не разметка NAND и не форматирование носителей.

| Каталог | Назначение |
|---|---|
| `/SPMP_OS_FILES.bin` | Текущая запускаемая RAM-оболочка; пользовательский entry point |
| `/SPMP-OS/System/Apps` | Устанавливаемые системные приложения, когда появятся соответствующие пакеты |
| `/SPMP-OS/System/Cores/Atari2600` | Первый запланированный эмуляторный пакет; сейчас каталог зарезервирован |
| `/SPMP-OS/System/Lib` | Сменные системные библиотеки/службы по будущему package API |
| `/SPMP-OS/System/Fonts` | Прямой TTF Roboto, metadata, лицензии; резервный bitmap встроен в BIN |
| `/SPMP-OS/System/Themes` | Будущие новые темы после описания дизайна пользователем |
| `/SPMP-OS/System/INSTALL.json` | Описание версии структуры и SHA entry point |
| `/SPMP-OS/User/ROMs/Atari2600` | ROM Atari, отдельные от кода эмулятора; произвольные имена |
| `/SPMP-OS/User/Ports` | Пользовательские игровые данные портов |
| `/SPMP-OS/User/Music` | Музыка |
| `/SPMP-OS/User/Video` | Видео |
| `/SPMP-OS/User/Pictures` | Изображения |
| `/SPMP-OS/User/Books` | Книги |
| `/SPMP-OS/User/Saves/Atari2600` | Сохранения/состояния, когда соответствующий backend будет подключён |
| `/SPMP-OS/User/Settings` | Пользовательские предпочтения, отдельно от заводских defaults |
| `/SPMP-OS/User/Logs` | Диагностические журналы, включая SPMPFM.CSV |

Пустой каталог не означает уже установленный модуль. Обновление приложения
или библиотеки должно затрагивать System, сохраняя User. Установочный ZIP
не содержит ROM, оригинальных прошивок, Ghidra и закрытых OEM библиотек.
При распаковке обычные средства ОС могут спрашивать о замене существующего
BIN/системного шрифта; программа сама существующие файлы не мигрирует.

Расположение ROM не должно определять имя, которое ожидает ядро. Менеджер
выбирает относительный путь, SD backend преобразует его в абсолютный путь
в пределах `/fat20a0/hda0`, а `read_entire/file_size` передают его эмулятору.
Обновлённый z26 adapter уже использует этот контракт. Нынешний FM пакет
регистрирует выбор, исполняемый Atari module ещё не включён.

Другие имеющиеся ядра пользователь считает достаточно свежими: первоочередно
адаптируем их к общему API и собираем ARMv5TE/EABI5/soft-float. Массовое
обновление/замена third_party-версий без отдельной причины не требуется.
Atari 2600 зафиксирован первым рабочим эмулятором, FM — первым пользовательским
инструментом. Физическая встроенная память появится отдельным томом после
проверки разметки и одновременного доступа, а не переименованием System.
