# SPMP-OS — Defender Multi Mix Magic

**Незавершённая исследовательская база. Не готовая прошивка.**

Проект для Defender Multi Mix Magic / семейства Sunplus SPMP8000:
восстановление загрузки заводских RedBoot и `8000_MMI.RAP`, разработка
SPMP-OS и проверка будущих модификаций. Поддержка конкретной ревизии платы,
аппаратный HAL и загрузочный пакет ещё не подтверждены на устройстве.

## Содержимое

- `project/spmp-os/` — импорт исходников Stage49, интеграций FM01–FM05,
  мультимедиа и тем. Исторические README/STATUS сохранены как материалы
  передачи проекта; содержащиеся в них результаты не являются новой проверкой.
- `research/boot_reconstruction/` — [170 выбранных функций и контракты native API](research/boot_reconstruction/STAGE4_REPORT_RU.md),
  текущие результаты анализа загрузки,
  восстановленный на C инспектор MMPi и проверки по оригинальным образам.
- `research/Stage53_to_55/` — прежние инструменты исследования потоков и GUI,
  скрипты экспорта Ghidra и статические свидетельства.
- `docs/STATUS_ROADMAP_RU.md` — ограничения и дальнейшие задачи.
- `docs/IMPORT_PROVENANCE.json` — состав импорта из пользовательского архива
  и список исключённых файлов. Хеши относятся к исходному импорту, до правок.
- `docs/VALIDATION.md` — результаты проверок этой версии репозитория.

## Быстрая проверка без оригинальной прошивки

Требуются Python 3, C11-компилятор и Make:

```sh
make -C research/boot_reconstruction test
python3 tools/verify_integrity.py --quick
```

Сборка прототипа для компьютера:

```sh
make -C project/spmp-os host
(cd project/spmp-os && ./build/spmp-os-host --cores)
```

Проверки на компьютере не подтверждают работу на консоли. ARM-объекты
ET_REL также не являются загрузочной прошивкой.

## Локальные оригиналы

Оригинальные RAP/PRAW/IMG, восстановленные из них ELF/сегменты и базы Ghidra
не опубликованы. Разместите собственные оригиналы по путям из
[docs/LOCAL_INPUTS.md](docs/LOCAL_INPUTS.md). Они исключены из Git.
Отсутствие этих файлов не мешает публичным тестам инспектора; проверки
точных образов запускаются отдельно и требуют исходных SHA-256.

## Приоритет разработки

1. Восстановить проверяемый C/ASM-код загрузочного тракта.
2. Установить контракт памяти, MMU/cache и аппаратной инициализации.
3. Восстановить API eCos, файловой системы, дисплея, ввода и запуска приложений.
4. Интегрировать новую оболочку, сохранив необходимые штатные службы.

Сейчас нет полной реконструкции исходников RedBoot/MMI и подтверждённого
способа загрузки SPMP-OS на конкретной Defender. Оригинальные файлы не менять.
